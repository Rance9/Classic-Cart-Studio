@section Getting Started

@topic start
@title Start Here
@summary What CCS Console Workbench does, what works without a console, and the first things to do.

## What Workbench does

CCS Console Workbench takes care of the built-in storage of your Classic console: the NES Classic Mini or the SNES Classic Mini, chosen at the top of the window. It is part of Classic Cart Studio, by Rance9. With it you can:

- make a complete, checked backup of the console on this PC
- look through any console backup on this PC and copy files out of it
- check a backup file, and make a repaired copy of a damaged one
- put a backup back on the console it came from
- set the console up for CCS HOME, the game menu Classic Cart Studio puts on the console, and later undo that
- design how CCS HOME looks, and move saves and games between your own consoles

CCS HOME is separate from the console's original menu. Setting it up is your choice. Backing up, browsing and repairing backups never need it.

## What works without a console

**Backup Browser** and **Backup Repair**, under **Backup Files** in the side column, work only with files on this PC. They never need a console, a USB cable or a USB driver, and they never change a console. You can open, look through, check, copy and repair backups at any time.

## Console tasks in this version

! Each console task in this version has been built and checked on a PC for the NES Classic Mini, but stays turned off for a real console until it has passed testing on real NES Classic Mini hardware. This covers Back Up Console, the Console Browser check-up, Restore, Prepare Console, Return to Original Software, Console Rescue, Console Composer, CCS Mod and CCS Nucleus changes, Your System Images, Expert Mode and Developer Mode. If you start one with a real console, Workbench shows **Not available in this version**, and nothing on the console or this PC changes. Setting up the USB driver on this PC is turned off the same way.

For the SNES Classic Mini, Workbench's console tasks are being built and are not in this version yet, and none has been tested on a real SNES Classic Mini. With the SNES Classic Mini chosen at the top of the window, a console task's page says so and starts nothing: no console connection, no USB driver check, nothing written. Backup Browser and Backup Repair work the same whichever console is chosen.

You can still open every console page in this version and read what each task will do.

## Your first steps

1. Look at the **Dashboard**, at the top of the side column. It shows the first thing to do, the main tasks and your newest backups; the console line at the top of the window shows your console. See [The Dashboard](#dashboard).
2. Choose where new backups are saved: open **Settings** in the side column. An additional copy on a second drive is a good idea. See [Settings](#settings).
3. To make a backup, choose **Back Up Console** and follow its steps. See [Back Up Your Console](#backup) and [Connect Your Console](#connect).
4. Check a backup file whenever you like with **Check the File**. See [Check a Backup File](#check-file).
5. Already have a console backup on this PC? Choose **Open a Backup File…** to look through it. See [Look Through a Backup](#backup-browser).

[shot 00b-dashboard-empty | The Dashboard before the first backup: No backups in this location yet, with Open a Backup File… and Backup Locations.]

## How every console change works

Every task that changes a console follows the same steps, so nothing is written by surprise:

1. You start the console in its recovery mode and connect it. See [Connect Your Console](#connect).
2. Workbench checks which console it is. Most tasks then make a complete backup of the console as it is now, in the same session.
3. Workbench shows a review of exactly what would change. Nothing has been written yet.
4. You confirm. Many reviews have an **I understand** box to tick first.
5. Each part is written once and read back. If a step fails, the steps after it are not done, and nothing is retried.

Expert Mode and Developer Mode work a little differently: instead of a fresh backup before each change, you choose one of the console's backups as a dated restore point. See [Expert Mode](#expert) and [Developer Mode](#developer).

Some reviews can be confirmed only once, and only for a limited time. If the time has passed, go back and review again.

! Workbench never promises that a console can be brought back to an earlier state. Keep your backups, check them now and then, and keep an additional copy on another drive.

## Standalone or opened from Classic Cart Studio

Workbench comes two ways, with the same pages and the same steps:

| Where it runs | What is different |
| The standalone CCS Console Workbench | One program file, with no installer. Your settings are kept only while it is open, unless you save them to a settings file of your own; when it closes with settings that are not saved, it asks first. When it closes, it may also offer to remove the USB driver it set up. |
| Opened from Classic Cart Studio for Windows | Classic Cart Studio installs the same program file and opens it in a window of its own. Only one opens at a time: opening it again brings that window forward. It keeps working when Classic Cart Studio closes. It saves its settings automatically, with Classic Cart Studio's own settings. HOME Designer can also preview a design with the HOME menu Classic Cart Studio prepared on this PC. When it closes, it may offer to remove the USB driver it set up, as the standalone does; Classic Cart Studio itself never asks. |

For the parts of the window, see [The Workbench Window](#window). Words you may not know have a dotted underline where they appear: choose one to see what it means, or see the [Glossary](#glossary). For how Help works, see [Using Help](#using-help).

## Start here

**Start here** is the first thing to do: **Back Up Console**, with what a backup copies. Under it, a short line says that Workbench connects to a console only when you start a console task, and that backups already on this PC can be browsed, checked and repaired without a console or a USB driver.

## The console line above the Dashboard

The console line at the top of the window, above every page, names the console family Workbench works with and shows what the latest console task saw:

| What it says | What it means |
| Console not checked | No console task has run since Workbench opened. |
| Console not identified yet · session open | A console task has started, but has not yet worked out which console is connected. |
| Console 73f23039, identified at 2:12 PM · session open | A console task is working with that console now. |
| Console 73f23039, identified at 2:12 PM · session ended | The latest task identified that console and has finished. |

Workbench connects to a console only when you start a console task and follow its steps. **About This Console**, at the right of the console line, opens a window about the console Workbench works with; your page stays as it is. See [About This Console](#about-console).

## Recent backups

Up to four of your newest backups are listed, newest first. Each row shows when the backup was made, which console it came from, its size, and when its file last passed a check. If an additional copy was kept, the row says so. The label on the right shows the file's state:

| Label | What it means |
| Complete · file check passed | The file passed a full check on this PC. |
| Complete · not checked yet | The backup finished, but its file has not passed a check on this PC yet. |
| Changed since its last check | The file has changed since it last passed a check. Check it again. |
| Damaged · some files can be saved | The file did not pass its check, but some of its files still match their checksums. |
| Damaged | The file did not pass its check. |
| Incomplete: not a backup | The backup did not finish. Nothing in this file is used. |
| File not found | The file is no longer where it was saved. |

Each row has the buttons that fit its state:

| Button | What it does |
| Browse | Opens the backup in the Backup Browser. It is checked in full first. |
| Open What Can Be Saved | For a damaged backup: opens only the files that still match their checksums. |
| Check the File | Reads the whole file on this PC and compares every part with its checksums. See [Check a Backup File](#check-file). |

The list only reads file names, Workbench's records and a small description inside each file. It never runs a new check by itself.

! A passed file check means the file was intact when it was checked. It is not a test of restoring it to a console.

## When no backups are listed

Each case says what it means and what you can do. **Open a Backup File…** is always there, to open a console backup saved anywhere on this PC, and **Backup Locations** opens Settings.

- **No backups in this location yet**, the first time: the backup folder has not been made yet. That is normal: Workbench makes it when it saves your first backup. There is nothing to read again, so there is no refresh button.
- **No backups in this location yet**, with the folder already there: the folder holds no backups. If you copy a backup into it, choose the circular arrow beside Recent backups to read it again.
- **Your backup location is not available**: its drive is not connected or cannot be found, so Workbench cannot see the backups there. Connect the drive and choose the circular arrow, or choose another location.
- **Workbench could not read your backup location**: the folder is there, but Windows did not let Workbench read it. This does not mean you have no backups. **Technical details** shows what Windows reported, and **Copy Details** copies it.

@topic connect
@title Connect Your Console
@pages driver, driver-setup
@summary Start your console in its recovery mode for a console task, and understand the USB driver pages.

Every console task (a backup, a check-up, a restore or a change) talks to the console over its USB cable while the console is in its recovery mode. In recovery mode, a small program runs from the console's memory. Connecting does not install anything on the console.

! In this version, connecting to a real console and setting up the USB driver are turned off until they have passed testing on real hardware. Workbench then shows **Not available in this version**, and nothing on the console or this PC changes. See [Start Here](#start).

## What you need

- The console and its USB cable.
- A free USB port on this PC.
- The TV connected to the console, so you can see its screen.
- The console's USB driver on this PC. If Windows does not have it, Workbench asks before setting it up. It never installs a driver by itself.

## Start the NES Classic Mini in recovery mode

These steps are the NES Classic Mini's. Each of its console tasks shows them under **Connect the console**. Follow them before you choose the task's start button. Steps for the SNES Classic Mini come with its console tasks, which are not in this version yet: with it chosen, a task's page shows that note instead.

1. Turn the NES Classic Mini off with its POWER switch.
2. Connect the console to this PC with its USB cable.
3. Hold the console's RESET button.
4. Switch POWER on, and keep holding RESET for about 5 seconds. Then let go.
5. Look at the TV: it shows a Classic Cart Studio screen while the small program runs from the console's memory.
6. In Workbench, choose the task's start button, for example **Start Backup** or **Check the Console**.

Test Boot in Developer Mode is different: the TV stays dark while the console waits for this PC. See [Developer Mode](#developer).

Keep the USB cable connected and this PC on until the task finishes. While a console task runs, the other pages in the side column are locked; they open again when it finishes or is canceled. Only one console task can run at a time. If another one is already running, in this window, another Workbench window or Classic Cart Studio, Workbench asks you to wait for it to finish.

## When the task is done

The console stays on the Classic Cart Studio screen until you choose one of these on the result page:

- **Restart the Console**: the console restarts into its normal HOME. You can unplug the USB cable once the TV shows it.
- **Done**: Workbench leaves the console on that screen until you switch it off.

## The USB driver on this PC

Windows needs a USB driver to talk to your console. Workbench uses it only for console tasks: backing up, checking, restoring or changing the console. Opening, browsing, checking and repairing backup files never need it.

Before the first console task, Workbench reads this PC's list of USB drivers; reading changes nothing. If a driver it can use is already there, Workbench uses it and leaves it in place. It never replaces or removes another program's driver, such as Hakchi's.

If this PC has no driver for the console, the **USB driver setup required** page lists every change setup would make to this PC before anything happens:

1. A small driver package that tells Windows to use its own WinUSB driver for your console. It contains no driver program.
2. A new certificate, made for this setup only, added to this PC's Trusted Root Certification Authorities and Trusted Publishers lists so that Windows accepts the package. It can sign nothing else.
3. Nothing else is installed, nothing is installed on the console, and no other driver or certificate is replaced or removed.
4. Windows keeps its own record of the setup in its logs. Removing the driver later does not erase that record.

Setup needs administrator permission. In this version the page ends with **Setting up or removing the USB driver on this PC is not available in this version. Nothing on this PC was changed.** Choose **Back** to leave the page.

[shot 55-driver-setup | The USB driver setup required page, listing what setup would change on this PC.]

## When the driver cannot be used

| Page title | What it means and what to do |
| This PC's USB driver for the console cannot be used | A different USB driver, for example libusbK, is in use for the console on this PC. Workbench will not replace it, and nothing was changed. The page may also say that different USB ports on this PC use different drivers for the console. Choose Back. |
| This PC's USB drivers could not be read | Workbench could not read Windows' list of USB drivers, so the task did not start. Nothing was changed. Try again in a moment. |
| The USB driver cannot be set up | This PC has no driver for the console yet, and Workbench cannot set one up as things are, for example because a certificate from Hakchi's own driver setup is already on this PC. Nothing was changed. |

In each case, backup files on this PC can still be opened, browsed, checked and repaired. **Technical details** gives the exact finding, and **Copy Details** copies it.

[shot 55b-driver-cannot-use | The page shown when another program's USB driver is in use for the console.]

[shot 55c-driver-read-failed | The page shown when Windows' list of USB drivers could not be read.]

[shot 55d-driver-blocked | The page shown when the USB driver cannot be set up on this PC.]

## Removing the driver when Workbench closes

When you close Workbench, it asks **Remove the USB driver?** only if Workbench itself set up the driver and nothing else on this PC still needs it. This is the same whether you opened the standalone Workbench or opened Workbench from Classic Cart Studio. Removing it may mean setting up the driver again later, for Workbench or for Hakchi.

| Button | What it does |
| No — Keep Driver | Keeps the driver for next time, and Workbench closes. This is the default. |
| Yes — Remove Driver | Removes only the driver Workbench set up, then its certificate. Windows asks for an administrator's name and password. Your console and backup files are not changed. |
| Cancel | Keeps Workbench open. |

[shot 55e-driver-close-question | The Remove the USB driver? question, with No — Keep Driver as the default.]

If Windows can finish the removal only after a restart, Workbench says so and leaves it for that restart. It never restarts your PC. The certificate stays until the removal is finished. The next time Workbench opens, it reads its own records of driver changes and this PC's driver list (reading only) and tells you if a removal is still waiting.

[shot 55f-driver-removal-restart | The message that Windows needs a restart to finish removing the USB driver.]

[shot 55g-driver-startup-notice | The notice Workbench shows when it opens while a driver removal still waits for a restart.]

After the restart, once nothing on this PC uses the certificate, Workbench asks **Remove the USB driver's certificate?**

| Button | What it does |
| No — Keep Certificate | Keeps the certificate. You are not asked again. |
| Yes — Remove Certificate | Takes the certificate out of this PC's Trusted Root Certification Authorities and Trusted Publishers lists. |
| Ask Me Later | Asks again the next time Workbench opens. |

[shot 55h-driver-cleanup-question | The question about removing the USB driver's certificate after the driver was removed.]

## Technical details (NES Classic Mini)

- In recovery mode the console uses the USB identity 1F3A:EFE8.
- The driver package is ccs_console_usb.inf with its catalog. Windows' own WinUSB driver does the work.
- Workbench records each driver step before it happens, in the USB Driver Records folder in your backup location.

@topic files-kinds
@title The Kinds of Files
@summary The different files Workbench makes and uses, what each one holds, and which ones to keep private.

Workbench works with several kinds of files. They are different things, and none of them can be used as another.

| Kind of file | What it is |
| Console backup (.zip) | A complete copy of one console's built-in storage, made by Back Up Console. Restore a Backup puts it back on that same console. An NES Classic Mini's backup is named like NES Classic Backup 2026-11-15 1324 (console 73f23039).zip. |
| Classic Cart Studio backup (.ccs) | A collection or full Studio backup made in the Classic Cart Studio app, with its game files. It is not a console backup and is not used here. |
| Game save file | A battery save converted from a backup for Classic Cart Studio's player, saved with a report beside it. The backup itself is never changed. |
| Shared HOME Design (.ccshome) | Pictures and appearance settings for CCS HOME, made in HOME Designer. No games, saves or console files. |
| Shared Composition Plan (.ccsplan) | The choices for a console setup, made in Console Composer, with no game files, saves or private console details. It never changes a console by itself. |
| Private Restore Package (.zip) | Built by Console Composer for one console: copies of the files to put on that console. Its name starts with PRIVATE. |

## Other files Workbench writes

| File or folder | What it is |
| Additional copy of a backup | The same console backup, saved a second time in your additional copy location when that is turned on in Settings. |
| Incomplete backup | A backup that did not finish. It is kept and listed as Incomplete, and it is never used as a backup. |
| Repaired copy (.zip) | A new backup file made by Backup Repair, with "repaired" and the date in its name, and a repair report beside it. The damaged original is never changed. |
| Recovery data (.par2) | Extra data saved beside a backup, so that damage to the backup can be rebuilt later. See [Recovery Data](#parity). |
| One-file copy with recovery data (.zip) | A backup and its recovery data together in one file, to move or store them. |
| A folder of exported files | Files you copied out of a backup, with a list of every file and its checksum. It is not a backup and cannot be restored. |
| A folder of saved files (Copy Out) | Files Backup Repair could still save from a damaged backup, with a list of what could not be saved. It is not a backup and can never be restored. |
| Workbench settings (.json) | Your backup locations, saved to a file you choose. See [Settings](#settings). |
| Check reports | Reports from the optional scheduled check, in the folder you choose. |
| Records | Small files where Workbench notes what it did, kept in your backup location, such as the USB Driver Records folder. |

## Keep these private

- **Console backups.** They hold your console's own files and saves, and the console's system key. Do not share them.
- **Private Restore Packages.** They hold copies of your own files and the identity of the console they are for. Never share them.
- **An exported key file, startup image, ramdisk or raw NAND image.** The console's system key is in its startup software. Exporting the key file copies the key, and a whole startup image, its ramdisk or the raw NAND image can contain it too. Exporting a folder, a type, search results or a game from the Backup Browser skips only the separate key file: if that export includes a whole startup image, ramdisk or raw NAND image, keep it private as well.

## Files you can share

- **Shared HOME Design** files, made with Share… in HOME Designer. Share only pictures you have the right to share. See [Share a HOME Design](#design-share).
- **Shared Composition Plan** files. Check what a plan holds before you pass it on. See [Packages and Shared Plans](#package).

@end

## The side column

The side column on the left lists every part of Workbench. **Dashboard** is at the top. Under it are the groups **Console Operations**, **Backup Files**, **Advanced** and **Settings and Help**. Choose an entry to open its first page. The entry you are in is marked.

## The console line at the top

| Part | What it does |

## The status line at the bottom

The line at the bottom of the window says what Workbench is doing now: **No task running**, a task running on this PC or with the console, or a console session that is still open. When a newer version of Workbench is published, **Update available** appears at its right: choose it to open [About Workbench](#about-app).

## The title bar

The title bar names Workbench and the version you are running, for example **CCS Console Workbench — v0.11.4 (Preview)**. **(Preview)** marks a preview version. Workbench shows its own version in the title bar however it was opened, also from Classic Cart Studio.

## The window buttons

The buttons at the top right of the window are **Minimize**, **Maximize** (it becomes **Restore** while the window fills the screen) and **Close**. Double-clicking the title bar also fills the screen or brings the window back, and Windows' own keys work too (Windows key with Up or Down arrow). A window that fills the screen leaves the taskbar visible.

**Close** asks first when something is not finished, in this order:

1. **Save before closing?** lists, in one question, the work that is not saved: your settings (in the standalone), a settings change Workbench could not save, a HOME design with changes, and anything a page holds that is not kept. **Save & Close** saves them and closes; **Close Without Saving** closes and lets go of exactly the work listed; **Cancel** keeps the window open with everything as it was. If you cancel choosing a file, or a file cannot be saved, Workbench stays open, keeps your work and says what was not saved.
2. A console task that is running asks whether to stop it.
3. The USB driver question, only for a driver Workbench set up.

Canceling any of them keeps the window open with everything as it was. See [Settings](#settings) and [Connect Your Console](#connect).

## While a task runs

A progress page shows what the task is doing, a progress bar and the time so far. A task that writes to a console shows **Stop After This Part** or **Stop After This Step**: the part being written is finished and checked first, and then the task stops. A task that only reads shows **Cancel**, which stops at once.

[shot 54-progress | A progress page with its progress bar and its stop button.]

A task on this PC, such as checking a backup file, keeps going if you open another page; the status line at the bottom says when it finishes.

## Messages

When a task cannot start or stops with a problem, a message page says what happened and what was not changed. **Technical details**, when shown, has the exact finding, and **Copy Details** copies it. **Back** returns to the section you were in.

[shot 56-message | A message page: another console task is already running.]

## Results

Each task ends on its result page, which says what was done and what was not. The help topic for each task explains its results. After a console task, **Restart the Console** starts the console normally, and **Done** leaves it waiting on its screen until you switch it off.

## Reading about another console

The About This Console window has its own **Console to read about** choice. Choosing another console there only changes what the window shows: Workbench keeps working with the console it had, and nothing is saved.

When you close the window (with **Close**, its X or Escape) after choosing a different console, Workbench asks **Change console?**, because you selected a different console in Help than the one Workbench uses. The question shows **Current console** (the one Workbench uses now) and a **Use console** choice that starts on the console you chose in Help; you can still change it there.

| Button | What it does |
| Use Selection | Workbench works with the console in **Use console** from now on, as if you had chosen it at the top of the window, and the window closes. |
| Keep Current | The window closes and nothing changes. |
| Back to Help | The question closes and you are back in the window, on the console you chose. Escape and the question's X do the same. |

Choosing the same console as before, or going back to it, closes the window without asking; so does **Use Selection** with the current console in **Use console**. While a console task or session is open, Workbench cannot change the console it works with: the window says so, and you can keep reading. ## The 2016 NES Classic and CCS Nucleus

A system image and startup software are different things:

- **A system image** (a .hsqs file) is a console's system: its own software and built-in games. With CCS Nucleus, a system image you supply, for example one from your own 2016 NES Classic, can be added as one of Nucleus's choices. See [Your System Images](#firmware).
- **Startup software** (the kernel) is what the console's circuit board loads first; a system image does not replace it. A restore puts a console's own backup back on that same console, and Console Rescue repairs a console only from its own backup. Some steps replace a console's startup software on purpose and say so before you confirm: preparing a console replaces its startup software and bootloader, and a change you review in Developer Mode can replace its startup software. Return to Original Software puts back Nintendo's startup software and the console's own bootloader.

To add a 2016 system image with CCS Nucleus you need: a console prepared with CCS Nucleus (Prepare Console, or CCS Mod and CCS Nucleus), the system image file from your own console on this PC, and enough free room on the console. Workbench checks the file before anything is written. It never supplies, links to or downloads a system image.

! A system image from another version of the console has not been tested on a real console, and no 2016 console has been tested with Workbench. Workbench reads each console's own storage layout before any task and refuses one it does not know.

## How it works

It works in two parts:

1. In this session, Workbench puts back Nintendo's startup software and this console's original bootloader, removes hakchi's files and restores the original storage layout, as Hakchi2 CE's own uninstall does.
2. After the console restarts, Restore a Backup puts back the backup made before preparing, so the console's storage is exactly as it was then.

## What you need

- A console exactly as Classic Cart Studio's preparation left it. Anything else is refused.
- The backup made before preparing. Workbench made it when you prepared the console.

Workbench first backs the console up as it is now, so saves made since preparing are kept in that backup.

## Return the console

1. Open **Console Restore** in the side column and choose **Return to Original Software**. You can also choose **Return to Original Software…** at the bottom of the Prepare Console page.
2. Start the console in recovery mode, as the **Connect the console** steps show. See [Connect Your Console](#connect).
3. Choose **Check the Console**. Nothing is changed in this step.
4. Read **Review the Return**, tick the **I understand** box, and choose **Return Now**.
5. When the result says **Nintendo's software is back**, choose **Restore the Backup Made Before Preparing…**.
6. When Workbench asks, connect the console again the same way (on the NES Classic Mini: POWER off, hold RESET, POWER on). Then follow the restore steps. See [Restore a Backup](#restore).

**Back** on the first page returns to Console Restore without connecting.

## Review the Return

The review lists the steps in order:

1. The original Nintendo kernel back as the startup software, from the spare slot.
2. This console's original bootloader sent to the console's memory and checked there. Nothing is written in this step.
3. This console's original bootloader (u-boot) written, from the backup made before preparing.
4. The storage layout back to its original division, as hakchi's own uninstall does.
5. After the console restarts: Restore a Backup, with the backup made before preparing.

Your two backups are bound to this return: the one made before preparing and the one made just now.

A Game save file is a battery save converted for Classic Cart Studio's player, saved with a report beside it. The save in the backup is never changed.

1. Click the battery save's name to see its details.
2. Choose **Convert to a Game Save File**. Workbench checks the save.
3. Read what it found.
4. If it was converted, choose **Save the Game Save File…** and choose where to save it. A report (.conversion.json) is saved beside it.

[shot 42h-browse-save-convert | A sample battery save's details, with Convert to a Game Save File and the reason it was not converted.]

- When a game's entry is not yet confirmed on a real console, the result is a comparison copy only, saved with **Save the Comparison Copy…** for checking. It is never imported or put on a console.
- A file with the same name is never overwritten.

The same conversion works for a connected console's files in Console Browser.

## Technical details (NES Classic Mini)

- The console keeps each game's saves in its profile folder, clover/profiles/0/ followed by the game's code.
- The console's battery-save format starts with a 40-character check value of the rest of the file.

## Scheduled check (optional)

Windows can run CCS Console Workbench on a schedule to check your backup files on this PC. Nothing is scheduled unless you turn it on here. The check reads your backup locations from a settings file you saved, writes a report to a folder you choose, and shows a window only when it finds a problem. ## Technical details

- Rebuild finds the parts through the backup's repair map (its early copy of the part list), a careful read of a damaged ZIP index, or a walk through the ZIP part headers.
- Merge and Repair work in 1,048,576-byte pieces, and use a piece only when it matches its recorded checksum. Backups of another console are never used.
- A repaired file is written under a temporary name ending in .partial, checked in full from scratch, then renamed, never over another file.
- Copy Out copies only parts and files with a surviving recorded checksum. No checksum is ever made up.
- A supplied startup software file must equal the record exactly: its size, SHA-256 and MD5.

@topic parity
@title Recovery Data
@pages parity, parity-result
@summary Add recovery data beside a backup, so damage to the backup can be rebuilt later, and pack a backup and its recovery data into one file.

Recovery data, also called parity, is extra data saved beside a complete backup. If part of the backup is damaged later, the damaged blocks can be rebuilt from it, as long as enough of the recovery data is intact. The backup itself is only read, and the new files are written beside it.

! Recovery data does not help if the backup and its recovery data are both lost, for example with the drive they are on. Keep an additional copy on another drive too.

Open **Backup Repair**, then choose **Recovery Data** on a complete backup.

[shot 45-parity | Recovery Data for a sample backup, with How much recovery data and Unpack a One-File Copy….]

## Make recovery data

1. Choose **How much recovery data**: 5%, 10% (the default), 20% or 30% of the backup's size. More recovery data can rebuild more damage.
2. Choose **Make Recovery Data**.

Recovery data is made only for a backup that passes its full check.

## When a backup has recovery data

The page says **This backup has recovery data beside it**, with the number of files, and offers:

| Button | What it does |
| Check Against the Recovery Data | Checks the backup with its recovery data. |
| Make a One-File Copy with Recovery Data… | Puts the backup and its recovery data in one file, in a folder you choose, to move or store them. |

## Unpack a one-file copy

**Unpack a One-File Copy…** opens a one-file copy made here and writes its backup and recovery data into a folder you choose. It checks every part, rebuilds the backup from its recovery data when it is damaged, and runs the backup's full check. Unpacking never writes over a file.

## When recovery data is not available

If the page says recovery data cannot be made, checked or used in this copy of Workbench, the part it needs is missing from that copy, and its buttons do nothing. The result then says **Recovery data was not made**, and the files it read are unchanged.

[shot 45b-parity-result | Recovery data was not made, because this copy of Workbench cannot make it.]

**Back to Backup Repair** returns to Backup Repair. Escape does the same on the result page.

## Technical details

- Recovery data is PAR2 parity: an index file ending in .par2 and its volume files, beside the backup, with its settings recorded in a small file beside them. It protects the backup file only.
- A one-file copy is an outer ZIP holding backup/ (the backup), parity/ (its .par2 files) and transport.json (each part's SHA-256 and size), all stored without compression. The outer file is not itself protected by that recovery data.

@end

This puts the console back the way one of its backups recorded it. It changes the console, so it goes through Console Restore, which makes a fresh backup of the console as it is now, shows exactly what changes and asks you to confirm.

## Technical details (NES Classic Mini)

- Startup software: the console's active startup image (boot2), an Android boot image holding its kernel, ramdisk and command line. A startup image file must be an Android boot image in this console's own startup layout.
- System part: the console's root file system (rootfs on nandb), a SquashFS image, written through the console's own encryption.
- Data storage: any regular file, including hakchi/rootfs/ (hakchi's system overlay); never a link, a folder or a device.
- Never written in Developer Mode: the startup stages boot0 and boot1 (u-boot), the storage table, and hakchi's spare startup slot (boot2 slot 68), which holds the original kernel that Return to Original Software depends on.
- Test boot: the console waits in its built-in USB boot mode (FEL) and is identified by its hardware ID (SID), which is compared with the restore point's console before anything is sent. The image is sent to its memory once and started.
