# Where the backup prerequisite and the write boundaries are enforced

Every Classic Cart Studio change to a console is refused at more than one layer, by code that has no switch, setting, environment variable
or request field to skip it.

| Write path | Layer 1 (backend / window) | Layer 2 (worker, lowest write boundary) | Physical boundary (code constant) |
|---|---|---|---|
| HOME install, update, repair | `console_home.Dispatcher._physical`: `backup_admission.admit` (the console worker's `--admit-backup`, i.e. `CcsBackup.Engine.Admission.Admit`: this console's backups verified from scratch; the oldest recovery baseline required) before the single-use confirmation is used and before any worker starts; the admission rides in the run's arguments | `console_engine.worker._run_session` sends `admit` before the operation's body; `CcsWorker.Protocol.WorkerServer` refuses every write command (`put mkdir rmdir rename remove pointer module-install module-uninstall`) with `backup-required` until `admit` succeeded on THIS connection (`Admission.Use`: the ticket exists, matches the operation, subject and the console identity the worker reads itself, is under 10 minutes old, has not been used; its backup files verify again; it is then marked used) | `console_engine.gate.PHYSICAL_WRITE_ENABLED`, `CcsWorker.Gate.PhysicalWriteEnabled` (asked per write command, before the admission) |
| HOME removal (keeping the console's CCS data) | as above, operation `uninstall` | as above | as above |
| HOME removal that deletes the console's CCS data | as above, operation `uninstall-data`: the newest verified backup is named as the current one | as above, and the console's current state is proven on THIS connection: `ConsoleOps.Tree` lists `/var/lib/ccs` (every folder, file SHA-256 and link) and `Admission.Use` compares it with that backup's file list; a save or file changed, added or removed since, or a list that cannot be read, refuses the change (`current-backup-required` / `current-unchecked`). Classic Cart Studio's own change history is only an early hint | as above |
| Recovery of an interrupted attempt (G3) | as above, operation `recover` | as above (the same live comparison) | as above |

| CCS Mod / CCS Nucleus: removal, or change from one to the other (Console Restore; both Workbench hosts) | `MethodEngine.Prepare`: hakchi 3.9.3 on the data storage, the method installed (hakchi's own package lists) and the transfer folder read with `ccsprep mstate` (read-only); anything waiting there other than this plan's own files refused; a protective capture in this session bound with its session; plan digest `ccs-method-plan/3` (includes the console's method, HOME and CCS Mod start state, and for a change the CCS HOME archive's size and SHA-256 and the start choice). `MethodEngine.Execute`: digest, nonce, expiry, session, console; the backup held read-only and verified again; the method state read again and unchanged; the record saved; only then is the confirmation used | `RecoveryConsole.PrepStep` asks the `WriteAuthority` before each step; `ccsprep` method writes only the image's own pinned package (SHA-256 checked) and unlist only a list naming ccs-mod or ccs-nucleus, each into hakchi's transfer folder through a new name and a rename, refused when hakchi is absent, a link is on the way or something else waits there, and read back from the storage mounted again read-only. hakchi applies it at the next normal start. A change to CCS Mod with CCS HOME at power-on chosen (off by default; digest line `modstart=`) first records CCS Mod's own setting (`ccsprep mstart`: the image's pinned `ccs-mod start-setting`, Classic Cart Studio's folder only, read back), which CCS Mod's install applies with its own `autostart` command | `Gate.ConsoleSessions` + `Gate.MethodWrites` |

**Every console model's data-level changes** (Expert and Developer Mode files, Console Composer and private restore packages, HOME designs, the Sega Mini menu pictures clean-up, CCS Mod and CCS Nucleus, system images, community mods; the NES Classic and the North American and European Super NES Classic alike) also check, before any backup or write: the model's own capability (`ConsoleModels.RefusalFor`), and that the console's storage table puts its one data part on nandc, the only device the console programs mount (`ConsoleData.Refusal`). Files move between consoles only of the same model, and a Super NES Classic's only between consoles of the same region (`ConsoleData.RegionRefusal`). A session restore point is a backup of the same console and model. A Super NES Classic's saves are written as chosen, never through the NES Classic's converter. Adding a system image while CCS Nucleus's startup chooser is not installed places the chooser's package and its start setting in the same reviewed change, read back with the image.

**Not controlled by Classic Cart Studio:** Nintendo's own system and games writing their saves during normal play; the Classic Cart Studio
HOME's own saves on the console; any program the person starts independently (for example Hakchi2 CE itself). Classic Cart Studio does
not claim a lock on the hardware.

**One console operation at a time:** `ConsoleLock` (named mutex `Local\CCS.ConsoleOperation`), taken by the backup/restore/preparation
worker (both entry points) and by the HOME console worker at `connect`.

**What a ticket proves:** nothing by itself. `Admission.Use` requires a complete baseline entry for every change (and the current-state
entry its operation needs), verifies every one of those backup files again from scratch, and only then marks the ticket used; a missing,
empty, mistyped, incomplete or contradictory entry, or a ticket in the earlier version's form, refuses the change without consuming it.

**Tests:** `CcsBackup.Tests` (gate, admission, restore, prepare, return, lifecycle; snes and snes-system for the Super NES Classic), `CcsWorker.Tests` (admission: every write command, bypass
fields, identity, voiding, the write tier first, the production admitter, `--admit-backup`), `tools/companion/test_backup_admission.py`
(the dispatcher, the run arguments, the engine worker's `admit`, the production admitter with the built worker).
