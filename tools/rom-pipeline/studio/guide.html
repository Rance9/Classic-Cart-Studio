Getting Started · what customizing an NES Classic means

The NES Classic Edition (2018 North American model, CLV-101) ships with 30 games and a fixed menu. Customizing it means deciding what that menu shows: keep some of the 30, hide others, add games you own. The console's look and controls stay the same.

1ChooseSelect games in the Game Library. The selection is My Collection.
2PrepareThe Studio lays out the files and the selection on this PC in Hakchi2 CE's format and verifies the result.
3InstallHakchi2 CE transfers the prepared collection to the console. In this version you click that step in Hakchi yourself.
4PlayUnplug, power on, and the menu shows your collection.
Your games, your files. The Studio never downloads or distributes games. It organizes and prepares files you already own.
What changes on the console

A custom kernel (from the Hakchi project) is written once, after the original is backed up; it lets the console mount user storage. Your game files and menu entries are copied into that storage. Built-in games you leave unselected are hidden from the menu, not deleted; selecting them again restores them. Every change the Studio makes on this PC is backed up and can be undone.

Website vs Desktop App · what runs where

Classic Cart Studio is one Studio in two places. The website runs in your browser and needs nothing installed: browse, filter, build a collection, save it to a file, load it back, read this guide. Your collection lives in the browser's storage and never leaves your PC. Classic Cart Studio for Windows shows this same live website in its own application window and adds everything that touches files on your computer: reading your Hakchi library, keeping copies of imported ROMs, finding game files, preparing a collection, opening Hakchi2 CE.

Installing Classic Cart Studio · download, verify, install, upgrade, uninstall

1DownloadContinue in Desktop App shows the download when nothing is installed yet; or use the Releases page on GitHub. The file is ClassicCartStudio-Setup-<version>.exe.
2VerifyCompare the file's SHA-256 with the one shown next to the download (command below).
3InstallPer-user, no administrator rights. SmartScreen warns because the installer is unsigned; continue only if the hash matched.
4StartStart Classic Cart Studio from the Start menu. The Studio opens in its own window with the backend already connected.

Verification in PowerShell (letter case does not matter; the same value is in SHA256SUMS.txt on the release):

Get-FileHash -Algorithm SHA256 "$env:USERPROFILE\Downloads\ClassicCartStudio-Setup-<version>.exe"

Requirements: Windows 10 or 11 with Microsoft Edge (its WebView2 runtime displays the Studio) and an internet connection to load the website; if the website cannot be reached the application shows a recovery screen and keeps your data. Upgrade: run the newer installer; the program is replaced in place and your data is kept. Upgrading from the earlier NES Classic Collection Studio Companion (0.1.x) works the same way: imported games, personal games, collections and Hakchi setup stay where they were. Uninstall: Windows Settings → Apps. Your imported games, personal games and collections stay in %LOCALAPPDATA%\NESClassicCollectionStudio until you delete the folder.

Why the installer is not code-signed

A code-signing certificate costs money and binds a legal identity; the project has none yet. Every release is instead built by a public GitHub Actions workflow from the tagged source, with the run linked from the release notes, a build-provenance attestation attached, and the installer's SHA-256 published. The hash check is what protects you.

What the installer changes

Program files under %LOCALAPPDATA%\Programs\NESClassicCollectionStudio (the application, its backend and the WebView2 loader), a Start-menu shortcut, an optional desktop shortcut, and a per-user nesstudio:// link type that only opens or brings forward the application. No service, no scheduled task, no driver. The console USB driver is a separate step on the Install screen and is the only thing that asks for administrator approval.

Updates

The application never installs anything by itself. The website shows the newest release and tells you when the application on this computer is older than the website expects; the Studio menu's Check for updates opens the releases page. Website changes (help text, catalog, visual fixes) reach the application without a reinstall because the window shows the live website.

Understanding Game Versions · regions, revisions, re-releases, alternate ROMs

One game usually exists as several ROMs: regions, revisions, a Japanese original, a prototype, a later re-release. The Game Library lists each game once; the version chip next to the title (for example USA · Rev 1▾ 8) opens the list.

TermMeaning
RegionWhere the cartridge was sold (USA, Europe, Japan, World). Mostly language and timing differences.
Revision (Rev 1, Rev 2)A later manufacturing run with fixes. The highest verified US revision is the default recommendation.
Re-releaseThe same game as shipped in a later product (Virtual Console, compilation cartridges). Bytes may differ.
Prototype / Beta / SampleUnfinished or demonstration builds.
Pirate / UnlicensedNot published under Nintendo's license; includes legitimate independent releases.
Translation / HackA fan-modified ROM, kept as its own version of the original.

Your choice is kept exactly. A version you pick is never swapped for a "better" one, and a game loaded from your Hakchi library keeps the exact version that was there. Two versions of one game on the console at once is allowed: tick Keep more than one version of this game in the version list.

How versions are told apart

By content, never by file name: the SHA-256 of the file and of the headerless PRG+CHR data. Bytes that match the No-Intro database carry its name as a verified identity; a NesCartDB or Mesen match is shown as "cartridge DB"; anything else keeps its file name and is marked unverified. Two files with different names and identical bytes are one version.

Extended Library · everything beyond the curated set

The default library is a curated set of North American releases with complete metadata. The Extended Library switch (toolbar, second row) adds the rest of the index: other regions, prototypes and betas, unlicensed and pirate releases, re-releases, translations, multicarts, and extra versions of games already shown.

  • No duplicates: extra versions appear inside the existing version chip.
  • Some entries have incomplete metadata or unverified compatibility. The Studio says so rather than guessing.
  • Switching it off hides those games from browsing but never deselects them; selected ones stay in the Tray marked Extended.

Loading Existing Games · from your Hakchi library or a saved file

My Collection ▾ → Load Existing Collection has two sources.

AGames already on this computerThe companion reads Hakchi2 CE's games folder and config and shows what is there. Reading changes nothing.
BSaved collection fileA file from Save / Load. Selections, versions and decisions return exactly.

Selected Games Only vs Entire Game Library

Selected Games Only brings in the games currently ticked in Hakchi. Entire Game Library also brings in the unticked ones as available games; only the ticked ones are selected. With 400 games set up and 75 ticked you get 400 available and 75 selected, plus whichever built-in games were ticked, and the Studio names both parts in its count.

Known games are matched by their bytes, never by name. Unknown ones become personal games with their original name. A game whose ROM file is missing is listed, not dropped.

Adding Your Own Games · one file, described by you

1Pick a fileMy Collection ▾ → Add Your Own Games → Add one file and describe it; a .nes file or a ZIP containing one.
2IdentifyFile type, content hashes, iNES header (mapper, PRG/CHR sizes, mirroring, battery).
3Known or newA library match uses that version; anything else becomes a personal game with an editable title, version label, description and artwork.
4Managed copyThe companion keeps its own copy; your original is never modified.

Personal games take part in everything: search, grid, list, Tray, favorites, versions, Technical Details, saved files and preparation. They carry the Personal Game badge. For many files at once, see Adding Games from Files and Folders.

Headerless files cannot be prepared, because the Studio does not guess mappers. The game is kept and Technical Details says what is missing. If the companion's copy disappears, Locate File accepts only a file with the same bytes.

Adding Games from Files and Folders · ZIP archives, bulk import, exact identification

Add Your Own Games also offers files (any number of ROMs or ZIPs) and a folder (everything in it, recursively). Both run as a background job with progress, a running list and a summary. Stop at any time; what was already examined stays.

1ReadZIPs are read in memory, member by member. Unsafe paths, oversized members and zip bombs are refused and reported.
2Identify by contentHashes with and without the 16-byte header. A match is exact or it is not a match; names are never trusted.
3Keep one copyOne managed copy per known version; duplicates are counted, not copied. Unknown files become personal games.
4AddWhen the job finishes, one click adds the matched games to the collection.

Originals are never changed, moved or deleted. Limits: 8 MiB per file, 32 MiB per archive, 64 members per archive, 8 KiB minimum. Import only files you own; see Your Files, Ownership and Redistribution.

Missing Game Files · pending dependencies and Locate Game File

The index knows thousands of versions by hash, but a version can only be prepared when this PC has its file. A selected version without a file is a pending dependency: it stays in the collection, Check lists it as "missing ROM payload", and preparing waits until the file exists. Nothing is substituted; a different revision or region is a different game.

1Locate Game File…On the Check screen, in the missing game's row. Pick the file or a ZIP that contains it.
2Exact checkAccepted only when the content hash is that version; otherwise refused, nothing kept.
3DoneThe managed copy is kept; Check again and the row is green.

Importing a folder does the same for every known version it contains. The Check summary shows how many selected games have files on this PC and how many are missing.

Your Files, Ownership and Redistribution · what this project does and does not do with games

The Studio is a collection manager. It identifies games through public identification data (titles, publishers, hashes from the No-Intro, NesCartDB and Mesen databases). It contains no game files and no downloader. The ROMs it works with are the ones you provide and own, such as dumps of your own cartridges, plus the 30 games on your console.

  • Copies the companion keeps stay on your PC; nothing is uploaded.
  • Saved collection files hold names, hashes and choices, not game data, so they can be shared.
  • Mentions of the Internet Archive or similar sites in the documentation describe where identification data originates; they are not an invitation to download copyrighted games, and the Studio will not do it for you.
  • The pixel artwork, interface icons and box art are shown to identify and present the games: Nintendo's renderings from the NES Classic Edition system software, documented community sprite rips (origins in the footer parade) and community box-art scans. All rights remain with their owners.

First-Time Console Preparation · what happens before a console accepts games

A stock console runs only its original software. Four things happen once, in this order, each a real change to the console and each only with your explicit go-ahead. This version of the Studio describes them; Hakchi2 CE performs them.

1BackupThe original kernel and NAND are read, saved on this PC and verified. This is the way back to factory software.
2Custom kernelHakchi's kernel is flashed so the console can mount user storage. The original stays in the backup.
3Modules (hmods)Optional additions such as RetroArch, only when a game in your collection needs them.
4First syncThe prepared collection is transferred; unselected built-in games are hidden.
Never assume a console is stock. Hakchi2 CE reports whether a custom kernel is present; check that before anything else.

The transfer in Hakchi2 CE 3.9.3

Hakchi has no automation interface for synchronizing, so the transfer is a click in Hakchi. After Prepare Games, Hakchi opens with exactly your collection ticked.

  1. Finish Prepare Games (status prepared on this computer). Verify in the console-management app opens Hakchi and reads its list without clicking anything.
  2. Connect the console (Connecting Your NES Classic): POWER on for a modded console, the RESET procedure for a stock one. For a stock console, read Backups and Recovery first; Hakchi will offer the kernel steps.
  3. Hakchi's status bar must say Online. The game list on the left is your collection, already ticked.
  4. Click Synchronize selected games with mini. Do not disconnect while the transfer runs.
  5. Close Hakchi when it reports completion.
  6. Unplug USB, power-cycle, and check the menu on the TV.
The Studio's own step 6 stays disabled until console writing has been reviewed and approved for this project. The steps above are Hakchi2 CE's standard procedure.

Updating an Existing Console · later changes are smaller than the first setup

Once a console is modded, changing the collection is routine: adjust My Collection, run Prepare Games (only changes are prepared, games already prepared are reused by hash, removed games are unticked rather than deleted), connect with POWER on, synchronize in Hakchi. No kernel is reinstalled to add a game; modules are only needed when a new game requires them.

If your Hakchi library changed since you loaded it (for example you used Hakchi directly), Check Collection notices and offers to review the differences, reload what is on this PC, or keep your changes. Nothing is overwritten silently.

Future: Automatic Console Sync · what a later version may add

Today the Studio prepares everything on the PC and leaves the console writing to Hakchi2 CE, operated by you. A later version may drive those steps from the Install screen: detect the console, confirm the backup, synchronize, read the result back. None of that exists yet, and every unavailable step says so.

Whatever is added keeps the same rules: nothing is written to the console without an explicit go-ahead, the original software stays backed up and restorable, and every step reports what it actually did.

Emulators and Compatibility · kachikachi or RetroArch

The console's own emulator, kachikachi, handles the mappers used by the built-in games and many more, but not all of them. Games on mappers it does not support run through RetroArch with the FCEUmm core, an optional hmod on the console.

  • Every game shows a recommended emulator, derived from the header's mapper and from documentation and community reports. Nothing has been tested on this particular console, and the Studio says so wherever the recommendation appears.
  • A game that needs RetroArch is prepared anyway; Check reports the missing module as a prerequisite instead of pretending the game will run.
  • Known problem titles (audio glitches or crashes on kachikachi) carry a note with its source; Technical Details shows the evidence.

Special Controllers · accessory limitations, including light guns

The NES Classic has two Wii-style controller ports. Games that need other hardware (Zapper, Power Pad, R.O.B., Four Score, Miracle Piano and others) carry a controller icon in the Game Library and appear in the Tray's hardware warning.

  • Light-gun games (Duck Hunt, Hogan's Alley, Wild Gunman): the Zapper needs a CRT, and no light-gun solution has been verified on this HDMI console. They install fine but stay marked unverified.
  • Power Pad, R.O.B., Vaus, keyboards, pianos: no supported way to connect them; marked unsupported.
  • Four Score (3 to 4 players): not possible with two ports.
  • Games playable with standard controllers in some modes are marked optional or mode-specific.

The Studio does not recommend accessories and does not assume compatibility with hardware that has not been verified on this console.

Backups and Recovery · two kinds of backup, and what to do after an interruption

Console backups (original kernel and NAND, read before any change, verified by checksum, kept in two places) are the way back to factory software. Preparation backups are taken on this PC before every Prepare: the previous selection and files are kept so any run can be undone.

If something is interrupted

  1. During Prepare: the Studio rolls back to the previous setup and says what happened. Nothing is left half-written. Run it again once the cause is fixed.
  2. Hakchi does not start after Prepare: the collection is still prepared and verified; start Hakchi manually, or undo the run from the undo point shown.
  3. A sync to the console is interrupted (cable, power): reconnect and sync again; Hakchi transfers only what is missing. Never power off during a kernel step.

About the Technology · what is under the hood

Hakchi2 CE 3.9.3 does the console side: custom kernel, user storage, game folders, hmod modules, hiding built-in games, synchronization. The Studio does not reimplement any of it. It writes collections in the exact layout Hakchi reads (one folder per game with the ROM and its .desktop entry, plus the selection in Hakchi's config) and leaves the console to Hakchi.

  • Identification: SHA-256 of each ROM's bytes and of the headerless PRG+CHR data, matched against No-Intro and against the NesCartDB and Mesen cartridge databases; iNES headers for headerless files come from those databases, never guessed.
  • Companion: a loopback-only HTTP server on 127.0.0.1:8765. The website reaches it through CORS with an exact-origin allow list; access is granted per site by the pairing window and expires when the companion closes. Its data lives under %LOCALAPPDATA%\NESClassicCollectionStudio.
  • Preparation: every run keeps a backup, a journal and a ledger under hakchi-staging; a run with no changes is a verified no-op; interrupted runs roll back.
  • Source and formats: the project repository documents the collection file schema and the acceptance evidence; see Credits for licenses.

Troubleshooting · short answers, details on demand

"Install on NES Classic" checks and prepares but does not install

Correct for this version: console writing is disabled until it has been reviewed and approved for this project. Preparing is complete and verified; Installing Your Collection covers the sync in Hakchi.

The button shows a setup screen

The Studio requires Hakchi2 CE 3.9.3, exactly that build. If it is missing it offers to set it up from the verified package; if a different build is present it says so and leaves it alone.

"Hakchi is open — close it first"

Hakchi rewrites its config on exit, so the Studio never changes it while Hakchi runs. Close Hakchi, prepare again.

"The console is connected — disconnect it first"

Prepare is PC-only; it refuses to run with the console attached so nothing can reach the console by accident.

"cannot be prepared" or "Game File Missing"

Either the ROM has no header and the Studio will not guess a mapper, or the companion's copy of the file is gone: use Locate File with a file that has the same bytes.

My Hakchi library changed since I loaded it

Something changed the selection outside the Studio. Check Collection offers: review the differences, reload from this PC, or keep your changes. Nothing is overwritten until you choose.

Windows asks for administrator approval

Only the console USB driver needs it, once, after you click Install console driver. The Studio and the companion never run elevated.

The pill says "Connect to Your Computer" and nothing happens

Start the companion (Start menu → Classic Cart Studio Companion), then pill → Connect → Allow in its window. If the pop-up was blocked, use the link in the dialog or enter the 6-digit code the companion shows.

"Local network access blocked" or "could not be reached"

Edge and Chrome ask once whether a website may reach programs on your PC. If it was declined: lock icon left of the address → Permissions for this site → Local network access → Allow, then reload.

"Companion needs an update"

The website expects a newer companion. Pill → Get the companion, verify the hash, run the installer; your data is kept.

SmartScreen says "unknown publisher"

The installer is unsigned. Verify the SHA-256 as described in Installing the Companion; if it matches, More info → Run anyway.

The companion says the port is in use

Another program is listening on 8765, or an older companion is still running. Close it and start the companion again.

The companion was closed or restarted

Website access is forgotten when the companion closes, by design. Start it, pill → Connect → Allow. Imported games and collections are unaffected.

A file "could not be read" during import

The summary names the reason: not a ROM, too small, unsafe archive paths, suspicious compression, damaged ZIP. The file is skipped; nothing else is affected.

Where the companion keeps things

%LOCALAPPDATA%\NESClassicCollectionStudio: logs\companion.log (no tokens), exports (saved collection files), hakchi-staging (backup, journal and ledger per preparation run), personal (imported and personal game copies).

Classic Cart Studio for Windows

The window shows "The Studio website couldn't be reached"

The application displays the live website, so it needs an internet connection. Choose Try Again once you are online, or Check Connection to open Windows network settings. Your collections, imported game files and settings on this computer are untouched; nothing is lost while the website is unavailable.

"The Studio backend did not start" or a port message

The application starts a small backend on 127.0.0.1. If an older companion window from a 0.1.x release is still open, close it and choose Retry. If another program uses the port, close it or change port in %LOCALAPPDATA%\NESClassicCollectionStudio\companion.json. The Studio menu → Diagnostics shows the backend's answer and the log location (logs\desktop.log, logs\companion.log).

I chose Continue in Desktop App and nothing arrived in the application

Edge first asks whether the website may access apps on your device (choose Allow), then Windows asks whether to open Classic Cart Studio (choose Open). If the application window is open but shows nothing, give it a few seconds: it checks for handed-over collections when it connects and every 15 seconds after that. The website keeps your collection either way; Download Collection & Open in App saves a file you can load with Save / Load → Load Collection from File.

Launching the application again opened nothing new

That is intended: Classic Cart Studio runs one window at a time, and a second launch brings the existing window forward.
