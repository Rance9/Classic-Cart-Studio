Getting Started · what customizing an NES Classic means

The NES Classic Edition (2018 North American model, CLV-101) ships with 30 games and a fixed menu. Customizing it means choosing what that menu shows: keep some of the 30, hide others, add games you own. The console's look and controls stay the same.

1 · CollectAdd the game files you own to a collection of any size. Each file is checked by its content; the Game Catalog helps you look a game up.
2 · HOMEEvery collection has its own HOME, the console-style game menu. Play it in your browser or in the Windows app, or prepare it for an NES Classic.
3 · PrepareThe Windows app checks the game files and prepares the collection on this computer for Hakchi2 CE.
4 · InstallYou transfer it with Hakchi2 CE. Installing from the Studio itself is not available in this version.

Your First Start

The first time Classic Cart Studio starts (in a new browser, or after a new installation of the Windows app), it prepares the Included Games once by itself and opens their collection, ready to Play. If they cannot be prepared, a message says so, with Try Again. After that, every start returns to the collection you used last.

Your games, your files. The Studio never downloads games from anywhere else. The only game files it carries are the Included Games, which their authors let it share; it gets them from ClassicCartStudio.com (or the Windows app's own installation) when you play or add one. Everything else it organizes and prepares is a file you already own.
What changes on the console
  • A custom kernel from the Hakchi project is installed once, after the original is backed up. It lets the console use extra storage for games.
  • Your game files and menu entries are copied there.
  • Built-in games you leave out are hidden, not deleted; adding them back restores them.
  • Everything the Studio prepares on this computer is backed up first and can be undone.

How This Application Works · collections, HOME, the Game Catalog

Your games are organized in collections, and nothing else. A collection holds its games, their order and folders, and its HOME: the console-style game menu with its theme, folders and favorites. Classic Cart Studio always opens on the games of a collection; HOME plays them here, and Classic Cart Studio for Windows can prepare a collection for an NES Classic.

The Parts

  • Collection: the games you added with their game files, each in its exact version, with their order, folders and the collection's HOME appearance (theme, folders, favorites). Any size; the console's storage does not limit it. Keep as many as you like: a different arrangement is a different collection, and Duplicate in the collection menu makes a copy to start from (no game file is copied).
  • Personal games: game files that are valid NES games but match no version in the Game Catalog. The Studio marks them Personal Game.
  • Game Catalog: a lookup of identified games: curated North American releases, plus the Extended Library when switched on. Browsing it never changes a collection.
  • HOME: the open collection as the console's game menu. Play it here, or prepare it for an NES Classic.

Saved, Prepared, Installed

These are three different states. The status in the collection menu shows how far a collection got: saved in this browser, saved to a file, or prepared on this computer.

  • Installed on the console: Hakchi2 CE transferred it and the console menu shows it. The Studio does not do this in this version.

Requirements

Windows 10 or 11. The Studio's window uses the Microsoft Edge WebView2 Runtime, a separate, free part of Windows from Microsoft; it is not the Edge browser. Windows 11 includes it, and most Windows 10 computers already have it. The installer checks for it first. If it is missing, setup adds it quietly from its own copy of Microsoft's offline installer, with no internet connection needed. If that does not work, setup stops and says so, and Classic Cart Studio is not installed.

No internet connection is needed to use the Studio; the Game Catalog and its artwork are installed with the app.

Updating

The app checks for a newer version shortly after it starts and once a day while it is open. When there is one, a dot appears on the Studio button and a short note says so; nothing opens over what you are doing. Studio › Update to x.y.z… opens the Update Available dialog. Update Now downloads it, checks it against the release's published checksum, then closes the app, updates it and opens it again; nothing installs without it. Check for Updates… in the Studio menu checks right away, and Check for Updates Automatically turns the daily check off or on. You can also run a newer installer yourself. Your collections, games and settings are kept.

Uninstalling

Windows Settings → Apps. Your collections, imported games and settings stay in %LOCALAPPDATA%\ClassicCartStudio until you delete that folder. The Microsoft Edge WebView2 Runtime stays too, because other apps share it.

Why the installer is not code-signed

A code-signing certificate costs money and binds a legal identity; the project has neither yet. Instead, every release is built by a public GitHub Actions workflow from the tagged source, with the run linked from the release page, a build-provenance attestation attached and the installer's SHA-256 published. The hash check is what protects you.

What the installer changes
  • Program files under %LOCALAPPDATA%\Programs\ClassicCartStudio.
  • A Start menu shortcut and an optional desktop shortcut.
  • The classiccartstudio:// link type (it only opens the app or brings it forward).
  • The .ccs file type (made the default only if no other app has it).
  • The Installation Terms, the GNU General Public License and the third-party notices, in the program folder's legal folder, with what the optional usage reports contain. No record of your agreement is kept or sent.
  • The Microsoft Edge WebView2 Runtime, only if this computer has no usable one: added for your user from Microsoft's offline installer, which setup carries.
  • Your answer on the Usage and Diagnostics page, in usage-reporting.json in %LOCALAPPDATA%\ClassicCartStudio. An answer already saved there is kept. Setup sends nothing.

No service, no scheduled task, no driver. The console USB driver is a separate step in Install on NES Classic and is the only thing that asks for administrator approval.

Understanding Game Versions · regions, revisions, re-releases, alternate game files

One game often exists as several game files: regions, revisions, a Japanese original, a prototype, a later re-release. The Game Catalog lists each game once.

Your Version Is Your File

A game in a collection is the exact version of its game file. The Studio identifies it by content and never changes it by itself for a “better” one, and a game brought in from Hakchi2 CE keeps its exact version.

In the Game Catalog, clicktap the version chip next to the title (for example USA · Rev 1▾ 8) to see every known version of the game.

To keep two versions of one game, add both game files: each version is its own game in the collection.

The version list. Every known version of the game; the current one is marked.

Version Terms

TermMeaning
RegionWhere the cartridge was sold (USA, Europe, Japan, World). Mostly language and timing differences.
Revision (Rev 1, Rev 2)A later production run with fixes. The highest verified US revision is the default recommendation.
Re-releaseThe game as shipped in a later product (Virtual Console, compilation cartridges). The content may differ.
Prototype / Beta / SampleUnfinished or demonstration builds.
Pirate / UnlicensedNot published under Nintendo's license; includes legitimate independent releases.
Translation / HackA fan-modified game file, kept as its own version of the original.
How versions are told apart

By content, never by file name. A file that matches the No-Intro database carries its name as a verified identity; a NesCartDB or Mesen match shows as “cartridge DB”; anything else keeps its file name and is marked unverified. Two files with different names and identical content are one version. Technical Details shows the evidence.

Extended Library · everything beyond the curated set, in the Game Catalog

The Extended Library is part of the Game Catalog lookup. By default the Game Catalog is a curated set of North American releases with complete details. The Extended Library switch in Filter & Sort adds the rest: other regions, prototypes and betas, unlicensed and pirate releases, re-releases, translations, multicarts and extra versions of games already shown.

  • No duplicates: extra versions appear inside the existing version chip.
  • Some entries have incomplete details or unverified compatibility; the Studio says so rather than guessing.
  • Switching it off hides those games in the Game Catalog but never removes them from a collection: a collection always lists every one of its games, and these are marked Extended.
The switch is in Filter & Sort, below the filters.

How Games Are Matched

  • Known games are matched by content, never by name.
  • Unknown ones become personal games under their original name.
  • A game whose game file is missing there is named in a list after loading and is not added; add its file with Add Game Files.

Adding Your Own Games · Add Game Files, personal games

A game joins a collection with its game file: through Add Game Files, the Game Catalog's Add Game File…, or a backup, which carries the game file of every game. Add Game Files works on the website and in the Windows app. For many files at once, see Adding Games from Files and Folders.

1Choose Add Game FilesIn the toolbar (on a phone, Add in the bottom bar). The games join the open collection; if no collection is open, a new one is started.
2Pick the files.nes or .unh files, or ZIP archives that contain them. You can pick several at once.
3Each file is checkedBy its content. A file that is exactly a version in the Game Catalog joins with the catalog's details. Any other valid NES game file joins as a personal game. A file that is not an NES game file is reported and not added.
4Read the summaryIt lists what was added, what was already in the collection and what was not added, with the reason.

What the Studio Does with the File

  • Reads its content and its iNES header (mapper, memory sizes, mirroring, battery).
  • On the website it keeps a private copy of the file in this browser, so the game plays here. That copy is not a backup: keep your own files or a .ccs backup.
  • In the Windows app it copies the file into the app's own store on this computer. Your original is never changed.

Personal games work everywhere: search, list, grid, favorites, HOME, backups and Prepare. They carry the Personal Game badge and start with the file's name as their title. In Classic Cart Studio for Windows, Edit Game Details… in a personal game's Game Details changes its title, version label, description and artwork.

Files without a header cannot be prepared, because the Studio does not guess mappers. The game is kept, and Technical Details says what is missing. If a game's file is later lost, Locate Game File… accepts only a file with identical content (Missing Game Files).

Adding Games from Files and Folders · ZIP archives, many files at once

Add Game Files takes any number of game files and ZIP archives at once, on the website and in the Windows app. Your originals are never changed, moved or deleted.

1Choose the filesAdd Game Files, then pick any number of game files or ZIP archives.
2Let it runEach file is checked in turn, with progress. In the Windows app, Stop ends it at any time (what was already examined is kept), and Run in Background closes the window while it goes on.
3Read the summaryEvery game found is added to the open collection. The summary says how many were added, which were already in it and which files could not be read, with the reason.

A whole folder: in the Windows app, after collections arrive from the website, Find Game Files… checks a folder and its subfolders for their game files.

What Happens to Each File

  • In the Windows app every file is copied in small pieces, ZIPs one game file at a time, so large files and archives use little memory. Unsafe paths, links, password-protected or damaged archives and suspicious compression are refused and reported.
  • Files are identified by content. A match is exact or it is not a match; file names are never trusted.
  • One copy is kept per version; duplicates are counted, not copied.
  • Valid NES game files that match no version in the Game Catalog become personal games. A file that is not an NES game file is reported and not added.

Limits

No limit on archive size or the number of games. In the Windows app a game file must hold at least 8.2 KB (8,192 bytes); on the website a game file larger than 16 MB is refused, as no NES game is that large. The drive needs free space for the copies. Add only files you own; see Ownership and Redistribution.

Missing Game Files · Game file missing, and what to do

Every game in a collection needs its game file: kept in this browser on the website, or in the app's own store in the Windows app. If a game's file is later deleted or lost (for example when a browser's site data is cleared), the game stays in its collection, and a red mark on it says what is wrong:

  • ⚠ Game file missing: its game file is no longer here.
  • Wrong game version: the file here is a different version of this game, so it cannot be used for this one.
  • Not checked: the game files could not be read just now. That is not the same as missing: nothing is changed, and Check Again tries once more.

A panel above the games says how many games need their game file. Nothing is substituted: a different revision or region is a different game.

Fix a Game

1Open the markHover over the mark or focus it with the keyboard to see what it means; clicktap it for what to do. Game Details says the same.
2Locate Game File…Pick the file itself, or a ZIP that contains it. It is accepted only when its content is exactly that game and version; otherwise it is refused and nothing is kept.
3Or Remove from This CollectionTakes the game out of this collection only. Its saved games and Game Settings stay, and so do its file and any other collection it is in.

What a Missing File Stops

  • HOME needs the game file of every game. While any game of the collection lacks a usable one, Open HOME, a game's Show in HOME, the Open HOME button in HOME Settings and, in the Windows app, Install on NES Classic do not open; a dialog names the games, and clickingtapping a name shows its fix (HOME).
  • Play checks only the game you start, so the other games of the collection still play.

Ownership and Redistribution · what this project does and does not do with games

The Studio is a collection manager. It identifies games with public identification data (titles, publishers and file hashes from the No-Intro, NesCartDB and Mesen databases). It contains no downloader and no game files apart from the Included Games, which their authors share under free licenses. The game files it works with are the ones you provide and own, such as dumps of your own cartridges, plus the 30 games on your console.

  • Copies the app keeps stay on your computer; nothing is uploaded.
  • Collections hold names, versions and choices, not game files. A .ccs backup always includes the game file of every game: it is made on your device only, after you confirm that you have the rights to make it. Creating a backup does not grant permission to redistribute copyrighted games, and Classic Cart Studio offers no way to send backups to other people. It never uploads or hosts them.
  • Mentions of the Internet Archive or similar sites in the documentation describe where identification data comes from; they are not an invitation to download copyrighted games, and the Studio will not do it for you.
  • The characters, icons and walkway decorating the Studio are its own pixel art. The box art identifies the games, and the scene illustrations behind the HOME were made for the project and show its own characters; all rights in the games remain with their owners.

Saving, Backing Up and Restoring · the collection menu, .ccs backups, restoring

Collections save automatically: in this browser on the website, on this computer in the Windows app. Every start returns to the collection you used last.

Switch collections in the collection menu (the open collection's name ▾). There, New Collection…, Rename…, Duplicate and Remove… act on the open collection, and Manage Collections… renames, duplicates, removes or backs up any of them. Removing a collection keeps the game files, saved games and Game Settings. If you remove every collection, the Studio shows You have no collections, with Add Game Files…, Restore a Backup… and New Collection….

Backing Up

A .ccs backup is complete: every game it lists, with its game file and exact version. It opens on the website and in the Windows app, and has no size limit.

  • Back Up This Collection… (collection menu): one backup file of one collection: its games with their game files, its HOME settings (theme, folders, favorites) and your own artwork.
  • Back Up All Collections… (Studio menu): one backup file of all your collections with their game files, plus favorites and Game Settings; in the Windows app also every game's saved games (cartridge saves and the four save slots, including games in no collection), Play on PC Settings, controller setups and your custom artwork and text.

Only the games in your collections are backed up. Game files on your computer that are not in any collection are not included.

  1. Every game in the backup needs its game file. The Windows app uses the files it keeps. The website uses the files this browser keeps for playing; for any game without one, choose Choose Game Files… and pick the game files, a ZIP of them or a backup file that has them. Games without their file are listed, and the backup is made once every one is there.
  2. Confirm that you have the rights to make this backup. Creating a backup does not grant permission to redistribute copyrighted games.
  3. Choose where to save it. The Windows app shows where it was saved. A browser that cannot ask saves it to its downloads; where that is depends on the browser's settings.

The backup is made on your device; Classic Cart Studio never uploads it. Keep it somewhere safe, such as another drive.

Where the details of your own games here differ, yours are kept unless you choose to replace them.   • Windows app: it asks before it adds the game files to this computer.

Moving Saved Games Between Devices

Export Game Saves… (Studio menu) saves one file with the saved games of every game here: cartridge saves and the four save slots with their names. It holds no game files and nothing else, and it goes nowhere by itself: move it to another device yourself (for example with Files, a cloud drive or email), then choose Import Game Saves… there. Saves move between the website and the Windows app; the NES Classic's own saves are not part of this.

  • Every save in the file is checked before anything changes: a damaged save, a save of another game or one made by another version of the game player is not used.
  • You choose what happens with each save. A new save goes to its slot; one that differs from the save here is kept out unless you put it in an empty slot or choose to replace the one here. The newer date does not always mean more progress.

On the website it is kept in the browser with its slot, name and save time: Replaced Game Saves… (Studio menu) lists them, and Export These Saves… makes a Game Saves file of them; import that file to put one back, into an empty slot or in place of the one there (which is kept the same way). First-Time Console Preparation · what happens before a console accepts Classic Cart Studio's HOME

A console runs Classic Cart Studio's HOME on top of Hakchi2 CE 3.9.3's kernel and files. CCS Console Workbench installs them itself with Prepare Console (in Console Backup and Console Composer), in Classic Cart Studio for Windows or on its own; no other program is needed. 1 · BackupA verified backup of the console's original state (Back Up Console). Before anything changes, preparation backs the console up again as it is right then.

After the console restarts, Restore Console Backup with the backup made before preparing brings back its games and saves exactly as they were then. CCS Console Workbench · back up, restore, repair and compose your NES Classic

CCS Console Workbench is in Classic Cart Studio for Windows: the Console Workbench button at the top of the first screen, or the Studio menu. It is also available on its own as CCS-Console-Workbench.exe, one program that needs no installation and offers the same sections. You do not need a collection, games, controllers or a HOME to use it. The website cannot read a console, so it has no Workbench.

It opens on its Dashboard: the console it works with (the NES Classic Mini or the SNES Classic Mini, chosen at the top of its window), whether a console has been checked in this session, Back Up Console, the common tasks and your most recent backups. Nothing connects to a console until you start a console task. Settings holds your backup location and an optional additional copy; Help and About explains the kinds of files Workbench uses and which tasks read or change a console.

Sections

  • Console Backup: a complete, checked backup of the console's built-in storage.
  • Console Restore: a backup put back on the same console, and the way back from Classic Cart Studio's preparation.
  • Console Rescue: when a startup stage is damaged, this console's own copy written back from one of its backups.
  • Console Composer: setting up a console from your own backups and files, fresh with Classic Cart Studio, or like another console; HOME Designer.
  • Console Browser: a check-up of the console (its startup software, what is installed, storage used and free) and its files; Expert Mode inside it changes your own game files, saves, artwork and settings.
  • Backup Browser and Backup Repair: your backup files, by game, by type or as stored, without a console.
  • Developer Mode: a separate area for changing files anywhere on the console's data storage.

Back Up Console

  • It copies everything on the console's built-in storage: the startup software, Nintendo's system and its built-in games, every save and setting, and anything other programs added (games, emulators, modules, menus, scripts), exactly as stored. Games and saves on USB or SD storage connected to the console are not included.
  • The console is connected to this PC in its recovery mode. On the NES Classic Mini: turn it off, connect its USB cable, hold RESET, switch POWER on and keep holding RESET for about 5 seconds. A small Classic Cart Studio program runs from the console's memory and only reads its storage.
  • The result is one file (about 1 GB) in your backup location, plus an additional copy if you set one up in Settings. Each copy is read back in full and checked before the backup is called complete. Two copies on the same drive protect against a damaged file, not against losing the drive.
  • If the program is closed or stops during a backup, the console is unchanged and the unfinished file is listed as Incomplete. It is never used as a backup.

Restore, Rescue and Composer

  • A backup is restored only to the console it came from, and only while that console's storage is laid out the same way.
  • Before anything is written, Workbench checks the backups it relies on, checks the console, makes a new backup of the console as it is now in the same session and shows exactly what will change. When you confirm, it checks those backups again and keeps them locked until it is done; if one is missing or changed, nothing is written.
  • Only what the plan names is written, each part read back from the console afterwards. If anything goes wrong, writing stops at once and nothing is retried.
  • Console Rescue writes a startup stage only from a backup of this same console. A black screen alone does not mean a stage is damaged; Workbench reads the stages first.

Backup Browser and Backup Repair

  • Backup Browser opens on the list of your backups (complete, incomplete, damaged or missing, with the date each was last checked). Open one to see it by game (game files, saves and suspend points together), by type or as stored, with search and a picture preview. Exports copy the files you choose to a new folder on this PC; each file is read back and compared with its checksum, and nothing is overwritten.
  • A damaged backup can still be opened to copy the files that still match their checksums. Even when the part holding the games and saves is damaged, each of its files is checked on its own against the checksum recorded when the backup was made: the ones that still match can be browsed and copied, and the rest are marked damaged. It stays marked damaged and is never used as a complete backup.
  • When a backup's table of contents is damaged, Find What Can Be Saved reads it (nothing is written to it) and offers three ways: browse it where it is, make a repaired copy in a folder you choose (it must pass the full check), or copy out the files that still match their checksums.
  • System images a backup holds (CCS Nucleus's own, or in hakchi's firmware folder) open under their own file: each file inside is listed with its details and can be previewed and copied. An image this version cannot read, or a damaged one, stays one whole file with the reason shown. The console's own system part is stored encrypted; the key its startup software uses is usually inside the backup's startup software, so its files open the same way, decrypted on this PC and never written anywhere. Without a key that opens it, it stays one exact file you can copy. The startup software opens too: its kernel, its ramdisk and the ramdisk's files. The system key file there is never shown and is copied only when you select it on its own; keep any copy private. The CCS HOME collection inside a backup (Console-HOME.ccs) opens the same way: its game files, its settings and its startup picture.
  • Each file shows where its checksum comes from: recorded when the backup was made, or worked out on this PC from the checked file it is inside.
  • Backup Repair checks backups and always makes a new file when it repairs one; the original stays exactly as it is.
  • Ways to repair a damaged backup: rebuild its table of contents, merge two copies damaged in different places, fill the damage from other backups of the same console (only where the pieces are byte-for-byte the same by their checksums), or copy out every file that can still be saved. Each way ends with a plain report of what was used, repaired and skipped.
  • When the console's startup software saved in a backup is damaged or missing in every copy, Supply a File (in Repair) can fill it in from an exact copy of that same file you already have on this PC. The file is used only if it has exactly the size and checksum the backup recorded for that part; anything else is refused and nothing is written. Classic Cart Studio does not provide or look for this file.
  • Recovery data (also called parity; PAR2) can be added to a complete backup: extra data beside it that can rebuild damaged parts later, as far as the recovery data itself is intact. A one-file copy puts a backup and its recovery data in one file to move or store; unpacking it checks every part and rebuilds the backup from its recovery data when needed.
  • An optional scheduled check can be turned on in Backup Repair: Windows runs CCS Console Workbench for your user to check your backups offline, and shows a window only when a check finds a problem. Nothing is scheduled unless you turn it on, and Remove Schedule takes it away.

HOME Designer and Shared Plans

  • HOME Designer (in Console Composer) changes how CCS HOME looks: your own pictures for its background, details backdrop, frame and icons, the startup picture, colors with the HOME's existing fonts, where its parts sit, folders and game order. A design is saved as a Shared HOME Design (.ccshome): pictures and settings only, with no games, saves or console files. Share only pictures you have the right to share.
  • A Shared Composition Plan (.ccsplan) holds your Console Composer choices and public references only. Whoever opens one sees a checklist of what they supply themselves; a plan never changes a console by itself and is never a restore point.
  • A private restore package holds your own files and is labeled private. It is never offered for sharing.
  • Check and Apply on My Console fits a design to your console's games (read from its newest backup) and draws every HOME screen with the console's own HOME program before it can be applied. Applying backs up the console first; Revert Design puts the previous look or the theme's own look back, keeping games and saves.

CCS Mod and CCS Nucleus

  • When a console is prepared, you choose how Classic Cart Studio starts on it: CCS Mod for Hakchi (CCS HOME as an entry in the console's own menu) or CCS Nucleus (a chooser at each start). Hakchi installs the chosen method at the console's next normal start.
  • Console Restore removes the method or changes between the two. Console Composer adds your own system images as CCS Nucleus choices; one starts only when it is chosen, and the console's own system always stays a choice.

The USB Driver

  • Before the first console operation, Workbench reads this PC's USB drivers (nothing is changed). A suitable driver already on the PC is used and left in place. If none is there, Workbench asks first, names every change it would make and needs administrator permission; it never replaces another program's driver.
  • When Workbench closes, it offers to remove a driver only when Workbench itself installed it and nothing else needs it. Keeping it is the default.

Expert Mode and Developer Mode

Before the first change, you choose a backup of this console as the restore point. It can be older than the console's current state. Restoring returns this console to that restore point. Changes and saves made after it are not protected. Each change is checked and read back; no full backup is made for each one. Developer Mode can change the console's own software: code you add controls the console once it runs, and a restore point cannot undo what that code does to the startup stages or the console's keys.

Keep the USB cable connected and the PC on while Workbench writes. An interrupted write can leave the console partly changed; no program can make that impossible.

Collection Backups Are Different

Back Up This Collection and Back Up All Collections make .ccs files of your collections and their game files on this computer. A console backup is a .zip of the console itself. About the Technology · what is under the hood

Hakchi2 CE 3.9.3 handles the console side: custom kernel, extra storage, game folders, modules (hmods), hiding built-in games, synchronizing. The Studio does not reimplement any of it.

The Studio writes your collection in the exact layout Hakchi2 CE reads (one folder per game with the game file and its .desktop entry, plus the selection in Hakchi2 CE's settings) and leaves the console to Hakchi2 CE.

  • Identification: the SHA-256 of each game file and of its headerless PRG+CHR data, matched against No-Intro and the NesCartDB and Mesen cartridge databases. Headers for headerless files come from those databases, never guessed.
  • Background Helper: Classic Cart Studio for Windows runs a helper process with a small HTTP server on 127.0.0.1:8765 for its own window (it is not a Windows service). The website may hand a collection or package to it (from ClassicCartStudio.com only) and nothing else. Its data lives in %LOCALAPPDATA%\ClassicCartStudio.
  • Preparation: every run keeps a backup and a journal; a run with no changes changes nothing; an interrupted run rolls back.
  • Play on PC: the game player (ccs-player.exe) runs the FCEUmm emulator (libretro-fceumm, built in, one pinned version) and the same HOME program as HOME in the Studio, in its own window. It reads the game files the app keeps and writes saves only to its own folder.
  • Console steps: they run in a separate worker process that, in this version, can talk only to a simulated console; physical installation is disabled in the code.
  • Backups: a .ccs file is a ZIP archive (ZIP64 when large) with a contents list of SHA-256 checksums and one game file per game, each verified by its content hash. A Full Studio Backup is the same format with every collection, the Game Settings and, from the Windows app, the saved games. It is made and read on your device only; Classic Cart Studio runs no service that receives backups or game files.
  • Source and formats: the project repository documents the collection and .ccs formats; see Credits for licenses.

How Classic Cart Studio is made

Classic Cart Studio runs on FCEUmm, an open-source NES emulator written by its own authors. I build it from unmodified source, pinned to one exact version. The included homebrew games are their creators' builds, unchanged, and the games you add are your own files. I didn't write the emulator or any of the games, and neither did my tools.

The app around them is what I build: the collection tools, the menus, the player, the installer and the help. I build it with AI agents. They write the code, and I direct the work. I set each task, review what comes back, send it back until it's right, and decide what ships. It's been a second job since day one, part-time every week on top of my full-time one.

Anything that touches a console stays switched off until it has passed on real hardware. Automated checks back that up: a pinned emulator version, game identification by file contents, and a public build record for every release.

The pixel characters and many of the icons and diagrams are drawn in code by the AI agents. Troubleshooting · short answers

Collections, Game Files and HOME

A game says “Game file missing”

Its game file is no longer kept: in this browser on the website (for example after the site's data was cleared), or in the app's store in the Windows app. ClickTap the mark:

  • Locate Game File… takes the file again. Only exactly that game and version is accepted.
  • Remove from This Collection takes the game out of this collection only. Its saved games, Game Settings and other collections stay.

Wrong game version means the file here is a different version of the game. Not checked means the game files could not be read just now; nothing was changed, so choose Check Again. See Missing Game Files.

HOME says it cannot open the collection

HOME needs the game file of every game. The dialog names the games without a usable one: clicktap a name for Locate Game File… or Remove from This Collection, then choose Open HOME again. Install on NES Classic checks the same way. To play one game meanwhile, use its ▶ Play: it checks only that game.

Play does not start a game

Play checks the game file of that game first. If the file is missing or is a different version, it says so, with Locate Game File… and Remove from This Collection. A file with no header the Game Catalog can supply cannot be played. Only one game window runs at a time; close it to start another.

The Included Games could not be prepared

On a first start the Studio checks the Included Games and keeps their files in this browser or on this computer. If that fails, the panel above the games says so: choose Try Again. Nothing was written, so the next start tries again too. Meanwhile you can add your own game files or restore a backup, and Add the Included Games… in the collection menu adds them later.

The Studio says “You have no collections”

Every collection was removed. Add Game Files… starts a new one with your games, Restore a Backup… brings back a .ccs backup, and New Collection… makes an empty one. For a while after a removal, Go Back to an Earlier Version… in the collection menu can bring a collection back.

That is expected: installing from the Studio is not available in this version. Preparing is complete and verified. Installing Your Collection explains the transfer in Hakchi2 CE; the console steps can be rehearsed against a simulated console.

I cannot find Install on NES Classic or Game Menu Setup

Install on NES Classic is in the toolbar; it prepares the open collection (on the website it invites you to the Windows app). The folders, theme and shortcuts of a collection's HOME are in HOME Settings… in the collection menu.

Hakchi2 CE rewrites its settings when it closes, so the Studio never changes them while it runs. Close Hakchi2 CE and prepare again.

Prepare says the console is connected

Prepare works only on this computer and refuses to run with the console attached, so nothing can reach the console by accident. Disconnect it and prepare again.

“Cannot be prepared” or “Game File Missing”

One of two causes:

  • The app's copy of the file is gone (the game is marked ⚠ Game file missing). Use Locate Game File… with a file that has identical content.
Hakchi2 CE's games changed since I loaded them

Something changed the selection outside the Studio. Check Collection offers to review the differences, reload from this computer, or keep your changes. Nothing is overwritten until you choose.

Windows asks for administrator approval

Only the console USB driver needs it, once, after you choose Install USB Driver…. The Studio never runs with administrator rights.
