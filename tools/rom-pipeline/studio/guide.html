Getting Started · what customizing an NES Classic means

The NES Classic Edition (2018 North American model, CLV-101) ships with 30 games and a fixed menu. Customizing it means choosing what that menu shows: keep some of the 30, hide others, add games you own. The console's look and controls stay the same.

1 · CollectPick games and exact versions from the Game Library into a collection of any size.
2 · PlanAn NES Classic Loadout picks the games from one collection that go on the console.
3 · PrepareThe Windows app checks the game files and prepares the loadout on this computer for Hakchi2 CE.
4 · InstallYou transfer it with Hakchi2 CE. Installing from the Studio itself is not available in this version.
The welcome screen. It opens at every start unless you clear Show at every start. Reopen it from Menu → Show the Welcome Screen.
Your games, your files. The Studio never downloads or distributes games. It organizes and prepares files you already own.
What changes on the console
  • A custom kernel from the Hakchi project is installed once, after the original is backed up. It lets the console use extra storage for games.
  • Your game files and menu entries are copied there.
  • Built-in games you leave out are hidden, not deleted; adding them back restores them.
  • Everything the Studio prepares on this computer is backed up first and can be undone.

The Parts

  • Game Library: curated North American releases, plus the Extended Library when switched on. Browsing it changes nothing.
  • Your own games: files you added. The Studio marks unknown ones Personal Game. They are not added to a collection automatically.
  • Collection: exact titles and versions, with your choices for the built-in games. Any size; the console's storage does not limit it.

Saved, Prepared, Installed

These are three different states. The status in the My Collections menu shows how far a collection got: saved in this browser, saved to a file, or prepared on this computer.

  • Installed on the console: Hakchi2 CE transferred it and the console menu shows it. The Studio does not do this in this version.

Requirements

Windows 10 or 11 with Microsoft Edge (its WebView2 runtime displays the Studio). No internet connection is needed; the Game Library and its artwork are installed with the app.

Updating

The app never updates itself and keeps the interface it was installed with. The website tells you when the app on this computer is older than it expects; Check for Updates in the app's menu opens the releases page. To update, run the newer installer; your collections, games and settings are kept.

Uninstalling

Windows Settings → Apps. Your collections, imported games and settings stay in %LOCALAPPDATA%\ClassicCartStudio until you delete that folder.

Why the installer is not code-signed

A code-signing certificate costs money and binds a legal identity; the project has neither yet. Instead, every release is built by a public GitHub Actions workflow from the tagged source, with the run linked from the release page, a build-provenance attestation attached and the installer's SHA-256 published. The hash check is what protects you.

What the installer changes
  • Program files under %LOCALAPPDATA%\Programs\ClassicCartStudio.
  • A Start menu shortcut and an optional desktop shortcut.
  • The classiccartstudio:// link type (it only opens the app or brings it forward).
  • The .ccs file type (made the default only if no other app has it).

No service, no scheduled task, no driver. The console USB driver is a separate step in Install on NES Classic and is the only thing that asks for administrator approval.

Understanding Game Versions · regions, revisions, re-releases, alternate ROMs

One game often exists as several ROMs: regions, revisions, a Japanese original, a prototype, a later re-release. The Game Library lists each game once.

Choosing a Version

Click the version chip next to the title (for example USA · Rev 1▾ 8) to open the list, then pick a version.

Your choice is kept exactly. The Studio never swaps a version for a “better” one, and a game brought in from Hakchi2 CE keeps its exact version.

To keep two versions of one game, check Keep more than one version of this game in the version list.

The version list. Every known ROM of the game; the current choice is marked.

Version Terms

TermMeaning
RegionWhere the cartridge was sold (USA, Europe, Japan, World). Mostly language and timing differences.
Revision (Rev 1, Rev 2)A later production run with fixes. The highest verified US revision is the default recommendation.
Re-releaseThe game as shipped in a later product (Virtual Console, compilation cartridges). The content may differ.
Prototype / Beta / SampleUnfinished or demonstration builds.
Pirate / UnlicensedNot published under Nintendo's license; includes legitimate independent releases.
Translation / HackA fan-modified ROM, kept as its own version of the original.
How versions are told apart

By content, never by file name. A file that matches the No-Intro database carries its name as a verified identity; a NesCartDB or Mesen match shows as “cartridge DB”; anything else keeps its file name and is marked unverified. Two files with different names and identical content are one version. Technical Details shows the evidence.

Game Details

Click details on a game for box art, year, publisher, genre, players, version, controller needs and Preview on TV for that game. Technical Details shows the header and identity evidence.

A game's details.

Extended Library · everything beyond the curated set

The default Game Library is a curated set of North American releases with complete details. The Extended Library switch in Filter & Sort adds the rest: other regions, prototypes and betas, unlicensed and pirate releases, re-releases, translations, multicarts and extra versions of games already shown.

  • No duplicates: extra versions appear inside the existing version chip.
  • Some entries have incomplete details or unverified compatibility; the Studio says so rather than guessing.
  • Switching it off hides those games from browsing but never removes them from a collection; they stay in the Tray marked Extended.
The switch is in Filter & Sort, below the filters.

How Games Are Matched

  • Known games are matched by content, never by name.
  • Unknown ones become personal games under their original name.
  • A game whose ROM file is missing is listed, not dropped; add the file with Add Your Own Game.

Adding Your Own Games · one file, described by you

Add a single ROM file in the Windows app. For many files at once, see Adding Games from Files and Folders.

1Open the actionAdd Your Own Game → Add One and Describe It…
2Pick a fileA .nes file or a ZIP that contains one.
3Describe it if neededA Game Library match uses that version. Anything else becomes a personal game with an editable title, version label, description and artwork.

What the Studio Does with the File

  • Reads its content and its iNES header (mapper, memory sizes, mirroring, battery).
  • Keeps its own copy; your original is never changed.

Personal games work everywhere: search, list, grid, Tray, favorites, versions, loadouts, exports and Prepare. They carry the Personal Game badge.

Files without a header cannot be prepared, because the Studio does not guess mappers. The game is kept, and Technical Details says what is missing. If the app's copy disappears, Locate File… accepts only a file with identical content.

Adding Games from Files and Folders · ZIP archives, many files at once

Add many ROM files or ZIPs at once in the Windows app. Your originals are never changed, moved or deleted.

1Choose the sourceAdd Your Own Game → Choose Files… (any number of ROMs or ZIPs) or Choose a Folder… (everything in it and its subfolders).
2Let it runThe job runs in the background with progress and a running list. Stop ends it at any time; what was already examined is kept.
3Add the matchesWhen it finishes, read the summary, then choose Add n Matched Games to add them to the open collection.

What Happens to Each File

  • ZIPs are read in memory, file by file. Unsafe paths, oversized files and suspicious compression are refused and reported.
  • Files are identified by content. A match is exact or it is not a match; file names are never trusted.
  • The app keeps one copy per known version; duplicates are counted, not copied.
  • Unknown files become personal games.

Limits

8 MiB per file, 32 MiB per archive, 64 files per archive, 8 KiB minimum. Add only files you own; see Ownership and Redistribution.

A version can be prepared only when this computer has its file. A version without a file stays in the collection; Check Collection lists it as missing, and Prepare waits until the file is there.

Nothing is substituted: a different revision or region is a different game.

Locate a File

2Choose LocateLocate ROM File… on the Check screen, Locate Missing ROM File… in details.
3Pick the fileThe file itself, or a ZIP that contains it. It is accepted only when its content is that exact version; otherwise it is refused and nothing is kept.

Ownership and Redistribution · what this project does and does not do with games

The Studio is a collection manager. It identifies games with public identification data (titles, publishers and file hashes from the No-Intro, NesCartDB and Mesen databases). It contains no game files and no downloader. The ROM files it works with are the ones you provide and own, such as dumps of your own cartridges, plus the 30 games on your console.

  • Copies the app keeps stay on your computer; nothing is uploaded.
  • Collections, .ccs exports and shared links hold names, versions and choices, not game files. Export with ROMs is the one exception: it is made on your computer only, after you confirm that you have the rights to the files, and you decide how to pass it on.
  • Mentions of the Internet Archive or similar sites in the documentation describe where identification data comes from; they are not an invitation to download copyrighted games, and the Studio will not do it for you.
  • The pixel artwork, interface icons and box art identify and present the games: Nintendo's renderings from the NES Classic Edition system software, documented community sprite rips (origins in the footer's character credits) and community box-art scans. All rights remain with their owners.

First-Time Console Preparation · what happens before a console accepts games

A stock console runs only its original software. Four things happen once, in this order.

Each is a real change to the console and happens only when you go ahead in Hakchi2 CE. The Studio describes them; Hakchi2 CE performs them.

1 · BackupThe original kernel and NAND are read, saved on this computer and verified. This is the way back to factory software.
2 · Custom kernelHakchi's kernel is installed so the console can use extra storage. The original stays in the backup.
3 · Modules (hmods)Optional additions such as RetroArch, only when a game in your loadout needs them.
4 · First transferThe prepared loadout is transferred; built-in games you left out are hidden.
Never assume a console is stock. Hakchi2 CE reports whether a custom kernel is present; check that first.

Console State

  • backup;

Installing Your Collection · loadouts, Install on NES Classic, the transfer in Hakchi2 CE

Plan a loadout, check and prepare it with Install on NES Classic, then transfer it with Hakchi2 CE.

NES Classic Loadouts

A collection can be any size; the console cannot hold everything. An NES Classic Loadout is a named set of games from one collection, planned for your console, with its own HOME Setup.

A collection can have several loadouts (for example “Family Favorites” and “Weekend Multiplayer”). Changing one never changes another or the collection.

  1. Open NES Classic Loadouts ▾ (on a phone, Loadouts in the bottom bar).
  2. Create a loadout. Start with all of the collection's games, or choose them.
  3. Uncheck games you want to leave out. This removes them from the loadout only.
  4. Choose Back to Collection to return to the whole collection.

A loadout is a plan: it says nothing about what is on a console. Exports, backups and shared links carry the loadouts with their collection.

Storage Estimate

While a loadout is open, the loadout bar shows its name and source collection, its game count and the NES Classic Storage meter. The meter is the one place the Studio estimates space. Its status is one of:

  • “Estimated to fit”
  • “Close to capacity: about X remaining”
  • “Estimated to exceed available space by X”
  • “Fit not confirmed: …”

Will it fit? breaks the estimate down: ROM files, artwork, the HOME menu, Hakchi, RetroArch when needed and a safety margin, against the space a stock console has.

Install on NES Classic

Install on NES Classic appears while a loadout is open (Install in a phone's bottom bar); from a collection, it first asks which loadout. On the website it invites you to the Windows app. In the app it has eight steps.

Steps 1 to 3 run on this computer:

  1. Check Collection: read-only. File present, exact version, compatibility, controller needs, estimated size and this computer's setup.
  2. Prepare Games: writes the files and selection into Hakchi2 CE's layout on this computer. Backed up first, verified after. Repeating it with no changes changes nothing.
  3. Connect Console: the connection steps, with read-only USB detection.
Check Collection, with the eight steps across the top.

Steps 4 to 8 are the console steps. In this version they run only against a simulated console: a built-in practice profile (stock in FEL mode, already modified, wrong model, no driver, little free space, a disconnect during the transfer and more), always marked SIMULATION.

  1. Console State: model, mode (FEL or normal), console software, whether first-time setup is needed, backup, capacity, modules, other games.
  2. Review Changes: games added and removed, versions changed, built-in games shown or hidden, modules, storage.
  3. Install: confirmation, then the installation with progress and safe points to cancel. The stages are Adding required components, Comparing with the console, Updating game files, Confirming the connection, Updating the HOME menu and Checking the result. Installing on a physical console is not available in this version; its button is shown disabled, and Rehearse Installation runs the sequence against the simulated console.
  4. Verify: an independent read-back compared with the plan, labeled known, estimated or unknown. After a failure it says what went wrong and how to recover.
  5. Complete: disconnect and test on the TV. It shows as complete only after a verified physical install; a rehearsal ends with a summary and never claims a physical install.

The Transfer in Hakchi2 CE 3.9.3

This is how to put a prepared loadout on the console in this version. Hakchi2 CE cannot be driven by another program, so the transfer is a click in Hakchi2 CE; after Prepare Games, it opens with exactly your loadout selected.

Stock console? Read Backups and Recovery first. Hakchi2 CE will offer the kernel steps.
  1. Finish Prepare Games (status: prepared on this computer).
  2. Connect the console (Connecting Your NES Classic): POWER on for a modified console, FEL mode for a stock one.
  3. Check that Hakchi2 CE's status bar says Online. The game list on the left is your loadout, already selected.
  4. Click Synchronize selected games with mini. Do not disconnect while the transfer runs.
  5. Close Hakchi2 CE when it reports completion.
  6. Unplug USB.
  7. Turn the console off and on again.
  8. Check the menu on the TV.

Updating an Existing Console · later changes are smaller than the first setup

Once a console is modified, changing its games is routine. No kernel is reinstalled to add a game; modules are needed only when a new game requires them.

AdjustAdd, remove or change versions in the loadout.
PrepareRun Prepare Games. Only the changes are prepared; unchanged games are reused, and removed games are unselected, not deleted.
ConnectPOWER on normally; the console appears as a network device.
SynchronizeIn Hakchi2 CE, which transfers only what is missing.

If Hakchi2 CE's Games Changed

If you used Hakchi2 CE directly since loading its games, Check Collection notices and offers to review the differences, reload what is on this computer, or keep your changes. Nothing is overwritten without your choice.

Future: Automatic Console Sync · what a later version may add

Today the Studio prepares everything on this computer, and Hakchi2 CE, operated by you, writes to the console.

The console steps in the Windows app already show the automatic path (console state, review, install with progress, verification) against a simulated console. A later version may run them on a physical console after real hardware testing: detect it, confirm the backup, transfer, and read the result back. Until then, every unavailable step says so.

Whatever is added keeps the same rules:

  • nothing is written to the console without your explicit go-ahead;
  • the original software stays backed up and restorable;
  • every step reports what it actually did.

Emulators and Compatibility · kachikachi or RetroArch

The console's own emulator, kachikachi, runs the mappers used by the built-in games and many more, but not all. Games on other mappers run through RetroArch with the FCEUmm core, an optional module installed on the console.

  • Every game shows a recommended emulator, based on its mapper, documentation and community reports, and the Studio says where each recommendation comes from.
  • A game that needs RetroArch is prepared anyway; Check reports the missing module as a prerequisite instead of pretending the game will run.
  • Known problem games (audio glitches or crashes on kachikachi) carry a note with its source; Technical Details shows the evidence.

Where to Look

Backups and Recovery · two kinds of backup, and what to do after an interruption

There are two kinds of backup, kept in different places.

  • Console backups are the way back to factory software: the original kernel and NAND, read before any change and verified. Keep copies in two places.
  • Preparation backups are made on this computer before every Prepare: the previous selection and files are kept, so any run can be undone.

If Something Is Interrupted

  • During Prepare: the Studio rolls back to the previous setup and says what happened. Nothing is left half-written. Run it again once the cause is fixed.
  • Hakchi2 CE does not start after Prepare: the loadout is still prepared and verified. Start Hakchi2 CE yourself, or undo the run from the undo point shown.
  • A transfer to the console is interrupted (cable, power): reconnect and synchronize again; Hakchi2 CE transfers only what is missing.
Never turn the console off during a kernel step.

About the Technology · what is under the hood

Hakchi2 CE 3.9.3 handles the console side: custom kernel, extra storage, game folders, modules (hmods), hiding built-in games, synchronizing. The Studio does not reimplement any of it.

The Studio writes your loadout in the exact layout Hakchi2 CE reads (one folder per game with the ROM and its .desktop entry, plus the selection in Hakchi2 CE's settings) and leaves the console to Hakchi2 CE.

  • Identification: the SHA-256 of each ROM file and of its headerless PRG+CHR data, matched against No-Intro and the NesCartDB and Mesen cartridge databases. Headers for headerless files come from those databases, never guessed.
  • Background Helper: Classic Cart Studio for Windows runs a helper process with a small HTTP server on 127.0.0.1:8765 for its own window (it is not a Windows service). The website may hand a collection or package to it (from ClassicCartStudio.com only) and nothing else. Its data lives in %LOCALAPPDATA%\ClassicCartStudio.
  • Preparation: every run keeps a backup and a journal; a run with no changes changes nothing; an interrupted run rolls back.
  • Console steps: they run in a separate worker process that, in this version, can talk only to a simulated console; physical installation is disabled in the code.
  • Sharing: Share Collection Link publishes a read-only copy (names, versions, loadouts, artwork; never game files) to the Classic Cart Studio sharing service at share.classiccartstudio.com, which refuses images that contain game data.
  • Source and formats: the project repository documents the collection and .ccs formats; see Credits for licenses.

Troubleshooting · short answers

Installing and Preparing

Install on NES Classic checks and prepares but does not install

That is expected: installing from the Studio is not available in this version. Preparing is complete and verified. Installing Your Collection explains the transfer in Hakchi2 CE; the console steps can be rehearsed against a simulated console.

I cannot find Install on NES Classic or HOME Setup

Both appear while an NES Classic Loadout is open. Open or create one from NES Classic Loadouts ▾.

Install on NES Classic shows a setup screen

The Studio works with Hakchi2 CE 3.9.3, exactly that build. If it is missing, the Studio offers to set it up from the verified copy included with the app. If a different build is present, it says so and leaves it alone.

Prepare says Hakchi2 CE is open

Hakchi2 CE rewrites its settings when it closes, so the Studio never changes them while it runs. Close Hakchi2 CE and prepare again.

Prepare says the console is connected

Prepare works only on this computer and refuses to run with the console attached, so nothing can reach the console by accident. Disconnect it and prepare again.

“Cannot be prepared” or “Game File Missing”

One of two causes:

  • The ROM file has no header, and the Studio will not guess a mapper.
  • The app's copy of the file is gone. Use Locate File… with a file that has identical content.
Hakchi2 CE's games changed since I loaded them

Something changed the selection outside the Studio. Check Collection offers to review the differences, reload from this computer, or keep your changes. Nothing is overwritten until you choose.

Windows asks for administrator approval

Only the console USB driver needs it, once, after you choose Install USB Driver…. The Studio never runs with administrator rights.

Website and Sharing

The website shows an invitation instead of the action

Actions that need your files (Install on NES Classic, Add Your Own Game, Export with ROMs) happen in Classic Cart Studio for Windows. Choose Open in Windows App: the app opens with your collections, or you are taken to ClassicCartStudio.com/app to install it.

“Local network access blocked” or “could not be reached”

Edge and Chrome ask once whether a website may reach apps on your computer. If you declined:

  1. Select the lock icon left of the address.
  2. Choose Permissions for this site.
  3. Set Local network access to Allow.
  4. Reload the page.
A shared link says it is not valid or was unpublished

The owner unpublished it, or the link is incomplete. Ask for a new link or a .ccs file.

A file “could not be read” while adding games

The summary names the reason: not a ROM, too small, unsafe paths in an archive, suspicious compression, a damaged ZIP. The file is skipped; nothing else is affected.

Classic Cart Studio for Windows

The app says it is older than the website expects

Install the latest version from ClassicCartStudio.com/app (verify the hash, run the installer). Your games and settings are kept.

SmartScreen says “unknown publisher”

The installer is unsigned. Verify its SHA-256 as described in Installing Classic Cart Studio; if it matches, choose More info → Run anyway.

“Classic Cart Studio couldn't load its interface”

The interface is installed with the app and served on this computer, so the app's Background Helper did not start. Choose Try Again; if it keeps happening, open Diagnostics or reinstall. Your collections, imported games and settings are untouched.

“Classic Cart Studio could not start”

The app runs a Background Helper on this computer (port 8765). If another program uses that port, close it and choose Try Again. Diagnostics in the app's menu shows the details and where the logs are.

If the Background Helper stops later, start Classic Cart Studio again from the Start menu. Your collections and imported games are unaffected.

I chose Open in Windows App and nothing arrived
  1. Edge asks whether the website may access apps on your device: choose Allow.
  2. Windows asks whether to open Classic Cart Studio: choose Open.
  3. If the app is open but shows nothing, wait a few seconds. It checks for collections when it starts and every 15 seconds after that.

The website keeps your collections either way. You can also export one as a .ccs file and open it in the app.

Starting the app again opened nothing new

That is intended: Classic Cart Studio runs one window at a time, and starting it again brings that window forward.

The console steps say “install the latest version”

The app on this computer is older than these steps need. Install the latest version from ClassicCartStudio.com/app; your games and settings are kept.

Export with ROMs is not available

It needs Classic Cart Studio for Windows, where your game files are. On the website, Export Collection (.ccs) exports everything except the game files.

Where the Windows app keeps things

In %LOCALAPPDATA%\ClassicCartStudio:

  • logs;
  • hakchi-staging: backup and journal for each Prepare run;
  • personal: copies of your own games;
  • console: installation plans and rehearsal records.
