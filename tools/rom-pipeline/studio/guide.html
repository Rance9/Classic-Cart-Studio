Getting Started · what customizing an NES Classic means

The NES Classic Edition (2018 North American model, CLV-101) ships with 30 games and a fixed menu. Customizing it means choosing what that menu shows: keep some of the 30, hide others, add games you own. The console's look and controls stay the same.

1 · CollectPick games and exact versions from the Game Library into a collection of any size.
2 · PlanAn NES Classic Loadout picks the games from one collection that go on the console.
3 · PrepareThe Windows app checks the game files and prepares the loadout on this computer for Hakchi2 CE.
4 · InstallYou transfer it with Hakchi2 CE. Installing from the Studio itself is not available in this version.
The welcome screen opens at every start unless you clear Show at every start; clicking outside it is the same as Just Browse. To see it again: Menu → Show the Welcome Screen.
Your games, your files. The Studio never downloads or distributes games. It organizes and prepares files you already own.
What changes on the console

A custom kernel from the Hakchi project is installed once, after the original is backed up; it lets the console use extra storage for games. Your game files and menu entries are copied there. Built-in games you leave out are hidden, not deleted; adding them back restores them. Everything the Studio prepares on this computer is backed up first and can be undone.

Requirements: Windows 10 or 11 with Microsoft Edge (its WebView2 runtime displays the Studio). Why the installer is not code-signed

A code-signing certificate costs money and binds a legal identity; the project has neither yet. Instead, every release is built by a public GitHub Actions workflow from the tagged source, with the run linked from the release page, a build-provenance attestation attached and the installer's SHA-256 published. The hash check is what protects you.

What the installer changes

Program files under %LOCALAPPDATA%\Programs\ClassicCartStudio, a Start menu shortcut, an optional desktop shortcut, the classiccartstudio:// link type (it only opens the app or brings it forward) and the .ccs file type (made the default only if no other app has it). No service, no scheduled task, no driver. The console USB driver is a separate step in Install on NES Classic and is the only thing that asks for administrator approval.

Updates

The app never updates itself. The website shows the newest release and tells you when the app on this computer is older than it expects; Check for Updates in the app's menu opens the releases page. The app keeps the interface it was installed with; a newer release brings changes.

Understanding Game Versions · regions, revisions, re-releases, alternate ROMs

One game often exists as several ROMs: regions, revisions, a Japanese original, a prototype, a later re-release. The Game Library lists each game once; the version chip next to the title (for example USA · Rev 1▾ 8) opens the list.

Your choice is kept exactly. The Studio never swaps a version for a “better” one, and a game brought in from Hakchi2 CE keeps its exact version. To keep two versions of one game, check Keep more than one version of this game in the version list.

The version list. Every known ROM of the game with its year, publisher, kind, identity and recommended emulator; the current choice is marked.
TermMeaning
RegionWhere the cartridge was sold (USA, Europe, Japan, World). Mostly language and timing differences.
Revision (Rev 1, Rev 2)A later production run with fixes. The highest verified US revision is the default recommendation.
Re-releaseThe game as shipped in a later product (Virtual Console, compilation cartridges). The content may differ.
Prototype / Beta / SampleUnfinished or demonstration builds.
Pirate / UnlicensedNot published under Nintendo's license; includes legitimate independent releases.
Translation / HackA fan-modified ROM, kept as its own version of the original.
How versions are told apart

By content, never by file name. A file that matches the No-Intro database carries its name as a verified identity; a NesCartDB or Mesen match shows as “cartridge DB”; anything else keeps its file name and is marked unverified. Two files with different names and identical content are one version. Technical Details shows the evidence.

Details. Click details on a game: box art, year, publisher, genre, players, version, controller needs, and Preview on TV for that game. Technical Details shows the header and identity evidence.

Extended Library · everything beyond the curated set

The default Game Library is a curated set of North American releases with complete details. The Extended Library switch in Filter & Sort adds the rest: other regions, prototypes and betas, unlicensed and pirate releases, re-releases, translations, multicarts and extra versions of games already shown.

  • No duplicates: extra versions appear inside the existing version chip.
  • Some entries have incomplete details or unverified compatibility; the Studio says so rather than guessing.
  • Switching it off hides those games from browsing but never removes them from a collection; they stay in the Tray marked Extended.
Where the switch is: Filter & Sort, below the filters. The game count grows when it is on.

Adding Games from Files and Folders · ZIP archives, many files at once

Add Your Own Game also adds files (any number of ROMs or ZIPs) or a folder (everything in it and its subfolders). Both run in the background with progress, a running list and a summary. You can stop at any time; what was already examined is kept.

Your originals are never changed, moved or deleted. Limits: 8 MiB per file, 32 MiB per archive, 64 files per archive, 8 KiB minimum. Add only files you own; see Ownership and Redistribution.

Ownership and Redistribution · what this project does and does not do with games

The Studio is a collection manager. It identifies games with public identification data (titles, publishers and file hashes from the No-Intro, NesCartDB and Mesen databases). It contains no game files and no downloader. The ROM files it works with are the ones you provide and own, such as dumps of your own cartridges, plus the 30 games on your console.

  • Copies the app keeps stay on your computer; nothing is uploaded.
  • Collections, .ccs exports and shared links hold names, versions and choices, not game files. Export with ROMs is the one exception: it is made on your computer only, after you confirm that you have the rights to the files, and you decide how to pass it on.
  • Mentions of the Internet Archive or similar sites in the documentation describe where identification data comes from; they are not an invitation to download copyrighted games, and the Studio will not do it for you.
  • The pixel artwork, interface icons and box art identify and present the games: Nintendo's renderings from the NES Classic Edition system software, documented community sprite rips (origins in the footer's character credits) and community box-art scans. All rights remain with their owners.

First-Time Console Preparation · what happens before a console accepts games

A stock console runs only its original software. Four things happen once, in this order. Each is a real change to the console, and each happens only when you go ahead in Hakchi2 CE. The Studio describes them; Hakchi2 CE performs them.

1 · BackupThe original kernel and NAND are read, saved on this computer and verified. This is the way back to factory software.
2 · Custom kernelHakchi's kernel is installed so the console can use extra storage. The original stays in the backup.
3 · Modules (hmods)Optional additions such as RetroArch, only when a game in your loadout needs them.
4 · First transferThe prepared loadout is transferred; built-in games you left out are hidden.
Console State (Windows app) shows what a connected console would report: mode (FEL or normal), console software versions, whether first-time setup is needed, backup, capacity. In this version it uses a simulated console and says so.
Never assume a console is stock. Hakchi2 CE reports whether a custom kernel is present; check that first.

Preview on TV · the console menu of a loadout, and HOME Setup

Preview on TV: the console HOME in the Arcade Grid theme

Preview on TV (the red-and-white AS SEEN ON TV badge, or the action in a game's details) shows the console HOME menu of an NES Classic Loadout: its games, in their exact versions and order, drawn at the TV's 16:9 shape. From a collection, it first asks which loadout to show, or creates one. Nothing is installed, scanned, uploaded or sent to a console. While the loadout is empty, the preview shows a clearly labeled sample: the 30 built-in games every NES Classic ships with.

The console's controls, nothing more. D-pad, A, B, START and SELECT. A launches a game (a labeled simulated launch: nothing runs here, but the launch is recorded in the play history as on the console). SELECT opens the game's details (Play Game, Add or Remove Favorite, the description). START opens the menu: Return to Games, Change Theme, Sort Games, Favorites, Recently Played, Settings, All Games, Browse and Search. B goes back. Keyboard: arrows, Enter or Z for A, Backspace or X for B, S for SELECT, M for START; hold a direction to repeat; Esc closes.
Four themes. Arcade Grid (the default: a bright pixel landscape, a cover grid, tabs on top), Box Art Showcase (moonlit boxes, one game center stage), Featured Shelf (left navigation, featured art, a shelf of covers) and Adventure Map (an illustrated overworld whose landmarks are the destinations). START → Change Theme shows all four; A applies one and keeps your place. The buttons above the screen are a shortcut.
Browse and Search. Browse lists your HOME Setup folders first, then automatic categories built from the loadout's game details. Search uses the same forgiving engine as the Game Library, over the loadout's games, with suggestions above an A to Z, 0 to 9 keyboard. SELECT on the keyboard jumps to the first result.
Read the labels. The side panel marks each statement known, estimated or unknown. Which games and versions are in the loadout is known; which game files are ready is known only in the Windows app; what is on your console is always unknown. Covers without box art are generated placeholders, marked GENERATED COVER.
Empty loadout. The 30 built-in games as a sample, labeled as such.

Each loadout has its own HOME Setup. Favorites and play history from the preview are kept with the loadout. A sort chosen under START → Sort Games only changes the view, never the loadout's order.

Installing Your Collection · loadouts, Install on NES Classic, the transfer in Hakchi2 CE

NES Classic Loadouts

A collection can be any size; the console cannot hold everything. An NES Classic Loadout is a named set of games from one collection, planned for your console, with its own HOME Setup. Create one from NES Classic Loadouts ▾: start with all of the collection's games, or choose them. A collection can have several loadouts (for example “Family Favorites” and “Weekend Multiplayer”); changing one never changes another or the collection.

While a loadout is open, the loadout bar shows its name, its game count and the NES Classic Storage meter, the one place the Studio estimates space: “Estimated to fit”, “Close to capacity: about X remaining”, “Estimated to exceed available space by X” or “Fit not confirmed: …”. Will it fit? explains the estimate. Unchecking a game removes it from the loadout only. Back to Collection returns to the whole collection. A loadout is a plan: it says nothing about what is on a console. Exports, backups and shared links carry the loadouts with their collection.

The transfer in Hakchi2 CE 3.9.3

Hakchi2 CE cannot be driven by another program, so the transfer is a click in Hakchi2 CE. After Prepare Games, it opens with exactly your loadout selected.

  1. Finish Prepare Games (status: prepared on this computer).
  2. Connect the console (Connecting Your NES Classic): POWER on for a modified console, the RESET procedure for a stock one. For a stock console, read Backups and Recovery first; Hakchi2 CE will offer the kernel steps.
  3. Hakchi2 CE's status bar must say Online. The game list on the left is your loadout, already selected.
  4. Click Synchronize selected games with mini. Do not disconnect while the transfer runs.
  5. Close Hakchi2 CE when it reports completion.
  6. Unplug USB, turn the console off and on, and check the menu on the TV.
Installing from the Studio is not available in this version; its Install step runs only as a rehearsal. The steps above are Hakchi2 CE's standard procedure and the way to transfer a prepared loadout today.

Updating an Existing Console · later changes are smaller than the first setup

Once a console is modified, changing its games is routine: adjust the loadout, run Prepare Games, connect with POWER on and synchronize in Hakchi2 CE. No kernel is reinstalled to add a game; modules are needed only when a new game requires them.

If Hakchi2 CE's games changed since you loaded them (for example, you used Hakchi2 CE directly), Check Collection notices and offers to review the differences, reload what is on this computer, or keep your changes. Nothing is overwritten without your choice.

Future: Automatic Console Sync · what a later version may add

Today the Studio prepares everything on this computer, and Hakchi2 CE, operated by you, writes to the console. The console steps in the Windows app already show the automatic path (console state, review, install with progress, verification) against a simulated console. A later version may run them on a physical console after real hardware testing: detect it, confirm the backup, transfer, and read the result back. Until then, every unavailable step says so.

Whatever is added keeps the same rules: nothing is written to the console without your explicit go-ahead, the original software stays backed up and restorable, and every step reports what it actually did.

Emulators and Compatibility · kachikachi or RetroArch

The console's own emulator, kachikachi, runs the mappers used by the built-in games and many more, but not all. Games on other mappers run through RetroArch with the FCEUmm core, an optional module installed on the console.

  • Every game shows a recommended emulator, based on its mapper, documentation and community reports, and the Studio says where each recommendation comes from.
  • A game that needs RetroArch is prepared anyway; Check reports the missing module as a prerequisite instead of pretending the game will run.
  • Known problem games (audio glitches or crashes on kachikachi) carry a note with its source; Technical Details shows the evidence.
Where to look. The list's Emulator column (Filter & Sort → Show technical details), the details dialog and Technical Details all show the recommendation and its reason.

Special Controllers · accessory limits, including light guns

The NES Classic has two controller ports (the Wii-style connector) on its front. Games that need other hardware carry a controller icon in the Game Library and a warning in the Tray. The Studio does not recommend accessories; it lists the input hardware each game is documented to need.

Backups and Recovery · two kinds of backup, and what to do after an interruption

Console backups are the way back to factory software: the original kernel and NAND, read before any change and verified. Keep copies in two places. Preparation backups are made on this computer before every Prepare: the previous selection and files are kept, so any run can be undone.

If something is interrupted

  1. During Prepare: the Studio rolls back to the previous setup and says what happened. Nothing is left half-written. Run it again once the cause is fixed.
  2. Hakchi2 CE does not start after Prepare: the loadout is still prepared and verified. Start Hakchi2 CE yourself, or undo the run from the undo point shown.
  3. A transfer to the console is interrupted (cable, power): reconnect and synchronize again; Hakchi2 CE transfers only what is missing. Never turn the console off during a kernel step.

About the Technology · what is under the hood

Hakchi2 CE 3.9.3 handles the console side: custom kernel, extra storage, game folders, modules (hmods), hiding built-in games, synchronizing. The Studio does not reimplement any of it. It writes your loadout in the exact layout Hakchi2 CE reads (one folder per game with the ROM and its .desktop entry, plus the selection in Hakchi2 CE's settings) and leaves the console to Hakchi2 CE.

  • Identification: the SHA-256 of each ROM file and of its headerless PRG+CHR data, matched against No-Intro and the NesCartDB and Mesen cartridge databases. Headers for headerless files come from those databases, never guessed.
  • Local service: Classic Cart Studio for Windows runs a small HTTP service on 127.0.0.1:8765 for its own window. The website may hand a collection or package to it (from ClassicCartStudio.com only) and nothing else. Its data lives in %LOCALAPPDATA%\ClassicCartStudio.
  • Preparation: every run keeps a backup and a journal; a run with no changes changes nothing; an interrupted run rolls back.
  • Console steps: they run in a separate worker process that, in this version, can talk only to a simulated console; physical installation is disabled in the code.
  • Sharing: Share Collection Link publishes a read-only copy (names, versions, loadouts, artwork; never game files) to the Classic Cart Studio sharing service at share.classiccartstudio.com, which refuses images that contain game data.
  • Source and formats: the project repository documents the collection and .ccs formats; see Credits for licenses.

Troubleshooting · short answers

Install on NES Classic checks and prepares but does not install

That is expected: installing from the Studio is not available in this version. Preparing is complete and verified; Installing Your Collection explains the transfer in Hakchi2 CE, and the console steps can be rehearsed against a simulated console.

I cannot find Install on NES Classic or HOME Setup

Both appear while an NES Classic Loadout is open. Open or create one from NES Classic Loadouts ▾.

Install on NES Classic shows a setup screen

The Studio works with Hakchi2 CE 3.9.3, exactly that build. If it is missing, the Studio offers to set it up from the verified copy included with the app; if a different build is present, it says so and leaves it alone.

Prepare says Hakchi2 CE is open

Hakchi2 CE rewrites its settings when it closes, so the Studio never changes them while it runs. Close Hakchi2 CE and prepare again.

Prepare says the console is connected

Prepare works only on this computer and refuses to run with the console attached, so nothing can reach the console by accident. Disconnect it and prepare again.

“Cannot be prepared” or “Game File Missing”

Either the ROM file has no header and the Studio will not guess a mapper, or the app's copy of the file is gone: use Locate File with a file that has identical content.

Hakchi2 CE's games changed since I loaded them

Something changed the selection outside the Studio. Check Collection offers to review the differences, reload from this computer, or keep your changes. Nothing is overwritten until you choose.

Windows asks for administrator approval

Only the console USB driver needs it, once, after you choose Install console driver. The Studio never runs with administrator rights.

The website shows an invitation instead of the action

Actions that need your files (Install on NES Classic, Add Your Own Game, Export with ROMs) happen in Classic Cart Studio for Windows. Choose Open in Windows App; the app opens with your collections, or you are taken to ClassicCartStudio.com/app to install it.

“Local network access blocked” or “could not be reached”

Edge and Chrome ask once whether a website may reach apps on your computer. If you declined: select the lock icon left of the address → Permissions for this site → Local network access → Allow, then reload.

A shared link says it is not valid or was unpublished

The owner unpublished it, or the link is incomplete. Ask for a new link or a .ccs file.

The app says it is older than the website expects

Install the latest version from ClassicCartStudio.com/app (verify the hash, run the installer); your games and settings are kept.

SmartScreen says “unknown publisher”

The installer is unsigned. Verify its SHA-256 as described in Installing Classic Cart Studio; if it matches, choose More info → Run anyway.

A file “could not be read” while adding games

The summary names the reason: not a ROM, too small, unsafe paths in an archive, suspicious compression, a damaged ZIP. The file is skipped; nothing else is affected.

Where the Windows app keeps things

%LOCALAPPDATA%\ClassicCartStudio: logs, hakchi-staging (backup and journal for each Prepare run), personal (copies of your own games) and console (installation plans and rehearsal records).

Classic Cart Studio for Windows

“Classic Cart Studio couldn't load its interface”

The interface is installed with the app and served on this computer, so the app's local service did not start. Choose Try Again; if it keeps happening, open Diagnostics or reinstall. Your collections, imported games and settings are untouched.

“Classic Cart Studio could not start”

The app runs a small local service on this computer (port 8765). If another program uses that port, close it and choose Try Again. Diagnostics in the app's menu shows the details and where the logs are. If the service stops later, start Classic Cart Studio again from the Start menu; your collections and imported games are unaffected.

I chose Open in Windows App and nothing arrived

Edge first asks whether the website may access apps on your device (choose Allow), then Windows asks whether to open Classic Cart Studio (choose Open). If the app is open but shows nothing, wait a few seconds: it checks for collections when it starts and every 15 seconds after that. The website keeps your collections either way; export one as a .ccs file and open it in the app instead.

Starting the app again opened nothing new

That is intended: Classic Cart Studio runs one window at a time, and starting it again brings that window forward.

The console steps say “install the latest version”

The app on this computer is older than these steps need. Install the latest version from ClassicCartStudio.com/app; your games and settings are kept.

Export with ROMs is not available

It needs Classic Cart Studio for Windows, where your game files are. On the website, Export Collection (.ccs) exports everything except the game files.
