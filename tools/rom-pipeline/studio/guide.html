Getting Started · what customizing an NES Classic means

The NES Classic Edition (2018 North American model, CLV-101) ships with 30 games and a fixed menu. Customizing it means choosing what that menu shows: keep some of the 30, hide others, add games you own. The console's look and controls stay the same.

1 · CollectPick games and exact versions from the Game Library into a collection of any size.
2 · PlanAn NES Classic Lineup picks the games from one collection that go on the console.
3 · PrepareThe Windows app checks the game files and prepares the lineup on this computer for Hakchi2 CE.
4 · InstallYou transfer it with Hakchi2 CE. Installing from the Studio itself is not available in this version.
Your games, your files. The Studio never downloads or distributes games. It organizes and prepares files you already own.
What changes on the console
  • A custom kernel from the Hakchi project is installed once, after the original is backed up. It lets the console use extra storage for games.
  • Your game files and menu entries are copied there.
  • Built-in games you leave out are hidden, not deleted; adding them back restores them.
  • Everything the Studio prepares on this computer is backed up first and can be undone.

The Parts

Why the installer is not code-signed

A code-signing certificate costs money and binds a legal identity; the project has neither yet. Instead, every release is built by a public GitHub Actions workflow from the tagged source, with the run linked from the release page, a build-provenance attestation attached and the installer's SHA-256 published. The hash check is what protects you.

What the installer changes
  • Program files under %LOCALAPPDATA%\Programs\ClassicCartStudio.
  • A Start menu shortcut and an optional desktop shortcut.
  • The classiccartstudio:// link type (it only opens the app or brings it forward).
  • The .ccs file type (made the default only if no other app has it).
  • The Installation Terms, the GNU General Public License and the third-party notices, in the program folder's legal folder, with what the optional usage reports contain. No record of your agreement is kept or sent.
  • Your answer to the optional usage reports question, in usage-reporting.json in %LOCALAPPDATA%\ClassicCartStudio. An answer already saved there is kept. Setup sends nothing.

No service, no scheduled task, no driver. The console USB driver is a separate step in Install on NES Classic and is the only thing that asks for administrator approval.

Understanding Game Versions · regions, revisions, re-releases, alternate ROMs

One game often exists as several ROMs: regions, revisions, a Japanese original, a prototype, a later re-release. The Game Library lists each game once.

Choosing a Version

ClickTap the version chip next to the title (for example USA · Rev 1▾ 8) to open the list, then pick a version.

Your choice is kept exactly. The Studio never swaps a version for a “better” one, and a game brought in from Hakchi2 CE keeps its exact version.

To keep two versions of one game, check Keep more than one version of this game in the version list.

The version list. Every known ROM of the game; the current choice is marked.

Version Terms

TermMeaning
RegionWhere the cartridge was sold (USA, Europe, Japan, World). Mostly language and timing differences.
Revision (Rev 1, Rev 2)A later production run with fixes. The highest verified US revision is the default recommendation.
Re-releaseThe game as shipped in a later product (Virtual Console, compilation cartridges). The content may differ.
Prototype / Beta / SampleUnfinished or demonstration builds.
Pirate / UnlicensedNot published under Nintendo's license; includes legitimate independent releases.
Translation / HackA fan-modified ROM, kept as its own version of the original.
How versions are told apart

By content, never by file name. A file that matches the No-Intro database carries its name as a verified identity; a NesCartDB or Mesen match shows as “cartridge DB”; anything else keeps its file name and is marked unverified. Two files with different names and identical content are one version. Technical Details shows the evidence.

ClickTap a game (its cover, its title or anywhere on its card or row, apart from its box and buttons) for Game Details: box art, year, publisher, genre, players, version, controller needs and Preview on TV for that game. ClickTap the cover in Game Details to see the full image. Technical Details shows the header and identity evidence. With a mouse, resting the pointer on a cover shows it larger.

Extended Library · everything beyond the curated set

The default Game Library is a curated set of North American releases with complete details. The Extended Library switch in Filter & Sort adds the rest: other regions, prototypes and betas, unlicensed and pirate releases, re-releases, translations, multicarts and extra versions of games already shown.

  • No duplicates: extra versions appear inside the existing version chip.
  • Some entries have incomplete details or unverified compatibility; the Studio says so rather than guessing.
  • Switching it off hides those games from browsing but never removes them from a collection; they stay in Games in This Collection, marked Extended.
The switch is in Filter & Sort, below the filters.

How Games Are Matched

  • Known games are matched by content, never by name.
  • Unknown ones become personal games under their original name.
  • A game whose ROM file is missing is listed, not dropped; add the file with Add Your Own Game.

What the Studio Does with the File

  • Reads its content and its iNES header (mapper, memory sizes, mirroring, battery).
  • Keeps its own copy; your original is never changed.

Personal games work everywhere: search, list, grid, Games in This Collection, favorites, versions, lineups, backups and Prepare. They carry the Personal Game badge.

Files without a header cannot be prepared, because the Studio does not guess mappers. The game is kept, and Technical Details says what is missing. If the app's copy disappears, Locate File… accepts only a file with identical content.

Adding Games from Files and Folders · ZIP archives, many files at once

Add many ROM files or ZIPs at once in the Windows app. Your originals are never changed, moved or deleted.

1Choose the sourceAdd Your Own Game → Choose Files… (any number of ROMs or ZIPs) or Choose a Folder… (everything in it and its subfolders).
2Let it runThe job runs in the background with progress and a running list. Stop ends it at any time; what was already examined is kept.
3Add the matchesWhen it finishes, read the summary, then choose Add n Matched Games to add them to the open collection.

What Happens to Each File

  • Every file is copied in small pieces, ZIPs one ROM at a time, so large files and archives use little memory. Unsafe paths, links, password-protected or damaged archives and suspicious compression are refused and reported.
  • Files are identified by content. A match is exact or it is not a match; file names are never trusted.
  • The app keeps one copy per known version; duplicates are counted, not copied.
  • Unknown files become personal games.

Limits

No limit on file size, archive size or the number of games. A ROM must hold at least 8.2 KB (8,192 bytes), and the drive needs free space for the copies. Add only files you own; see Ownership and Redistribution.

Ownership and Redistribution · what this project does and does not do with games

The Studio is a collection manager. It identifies games with public identification data (titles, publishers and file hashes from the No-Intro, NesCartDB and Mesen databases). It contains no game files and no downloader. The ROM files it works with are the ones you provide and own, such as dumps of your own cartridges, plus the 30 games on your console.

  • Copies the app keeps stay on your computer; nothing is uploaded.
  • Collections hold names, versions and choices, not game files. A .ccs backup always includes every game's ROM file: it is made on your device only, after you confirm that you have the rights to make it. Creating a backup does not grant permission to redistribute copyrighted games, and Classic Cart Studio offers no way to send backups to other people. It never uploads or hosts them.
  • Mentions of the Internet Archive or similar sites in the documentation describe where identification data comes from; they are not an invitation to download copyrighted games, and the Studio will not do it for you.
  • The characters, icons and walkway decorating the Studio are its own pixel art. The box art identifies the games, and the game illustrations behind the HOME are fan art; all rights in the games remain with their owners.

Saving, Backing Up and Restoring · My Collections, .ccs backups, restoring

Collections save automatically: in this browser on the website, on this computer in the Windows app.

Switch collections in My Collections. Manage Collections… renames, duplicates, deletes or backs up any of them.

Backing Up

A .ccs backup is complete: every game it lists, with its ROM file and exact version. It opens on the website and in the Windows app, and has no size limit.

  • Back Up Collection (My Collections; Back Up in a phone's bottom bar): one collection, with its NES Classic Lineups, HOME settings and your own artwork.
  • Back Up Everything (Studio menu): every collection, favorites and Game Settings; in the Windows app also every game's saved games (cartridge saves and the four save slots, including games in no collection), Play on PC Settings, controller setups and your custom artwork and text.
  1. Every listed game needs its ROM file. The Windows app uses the files it keeps; on the website, choose Choose ROM Files… and pick the ROM files, a ZIP of them or a .ccs file that has them. Games without their file are listed, and the backup is made once every one is there.
  2. Confirm that you have the rights to make this backup. Creating a backup does not grant permission to redistribute copyrighted games.
  3. Choose where to save it. The Windows app shows where it was saved. A browser that cannot ask saves it to its downloads; where that is depends on the browser's settings.

The backup is made on your device; Classic Cart Studio never uploads it. Keep it somewhere safe, such as another drive.

Back Up Collection.

Restoring

  • Choose My Collections → Import Collection…, or drop the file on the page. In the Windows app, opening a .ccs file in Windows does the same.
  • Every ROM file in it is checked first; an incomplete or damaged file is not restored.
  • Before anything changes, you see what the backup holds, what is already here and what cannot be used (with the reason). Collections already here are skipped; changed ones (even a changed lineup or HOME setting) are added as copies. Where Game Settings or saved games differ, yours are kept unless you choose to replace them; the Windows app first keeps the replaced files in a dated folder beside them. Controller setups are restored only if you choose (they work only with the same controllers).
  • Saved games are checked the way the game player checks them: a save of another game, a damaged save, or one made by another version or another kind of computer is not restored; it stays in the backup file.
  • Your own games keep their details and artwork, including what you chose yourself: a description you cleared stays cleared, and a later package does not fill it in. Where the details of your own games here differ, yours are kept unless you choose to replace them. A new Studio takes the backup's library view and opens its open collection; otherwise your view and open collection stay unless you choose to replace them.
  • If something cannot be saved, the restore puts back what it changed (the details of your own games too), checks it, and tells you exactly what is as it was. If a file cannot be put back, it names the file and where its original is kept, with Try Again.
  • Saved games are never changed while a game window is open: close the game window first, then restore or choose Try Again.
  • Windows app: it asks before it adds the ROM files to this computer.
  • Website: it keeps the games privately in this browser so they play here, and adds the backup's saved games to this browser (a saved game already here that differs is kept as it is). That copy is not a backup: keep the .ccs file. Saved games move between the website and the Windows app this way, both ways.
  • A Full Studio Backup needs this version of Classic Cart Studio or newer; earlier versions say they can't open it.

A restore adds; it deletes nothing you have.

Snapshots, Lists and Settings

  • Restore Previous Version… (My Collections) brings back automatic snapshots taken before bigger changes, such as loading games or deleting a collection.
  • Studio menu → Save Lists and Settings… saves every collection, favorites, Game Settings and snapshots to one JSON file, without any game files (it is not a backup of your games).
  • Studio menu → Restore Lists and Settings… adds everything from that file and deletes nothing.

Browser storage belongs to one browser and site; a backup or that file is how your data moves between them. No account is involved.

Playing Games · in Classic Cart Studio for Windows and on the website

Classic Cart Studio plays your games on this device: in Classic Cart Studio for Windows, and on the website in your browser. Both use the same built-in FCEUmm emulator, the same save slots, Game Settings and controls, and never contact or change a console.

Ways to Play

  • Preview Your Game Menu is the real HOME: A on a game (or a double-click) starts it right there in the TV picture, after its start choices. Pop Out moves the HOME, and a game you are playing, to its own window; closing that window brings it back. Close asks the game first. It is not offered for the 30-game sample.
  • Play on PC in a game's details (Windows app) plays that exact version in its own game window.
  • On the website a game plays from a private copy this browser keeps of its file: it is kept when you import a .ccs backup or choose the file once. That copy is not a backup; keep your own file or a .ccs backup.
  • On a phone the HOME and its games are shown in landscape: the game fills the screen with its buttons beside the picture, and turning the phone upright pauses it in its menu.

A game plays only from its own ROM file. If the file is missing, is a different version, or has no header the Game Library can supply, the button is unavailable and says why; nothing is substituted or guessed. One game window runs at a time; on the website that holds for every tab and window of the browser, and a Full Studio Backup is not restored there while a game is open.

Controls

  • Keyboard: arrow keys; A = Z or Enter; B = X or Backspace; SELECT = S; START = M. It plays the player no controller plays: Player 1, or Player 2 when a controller plays Player 1.
  • Second keyboard player: I, J, K, L; A = H; B = G; SELECT = T; START = Y. For two people sharing the keyboard: Player 2, only while no controller is connected.
  • Xbox-compatible controllers work at once: A, B, Back = SELECT, Start = START, D-pad or left stick. On the website, so does any controller your browser reports with the standard layout.
  • Other USB or Bluetooth controllers: set them up once. From the controller itself: until it is set up, the game window says so; hold one of its buttons that does nothing for three seconds and the setup opens for that controller. Or from the game menu: Controllers → Set Up a Controller…. The setup asks for each button in turn; Esc on the keyboard cancels it, and nothing is saved until the last step.
  • Which controller plays: with several controllers connected (USB, Bluetooth or wireless), Controllers → Choose Player 1's Controller… (or Player 2's) picks the one that plays. Press a button on a controller to find it in the list, then A on it. The choice is remembered. Until you choose, the first two controllers are Players 1 and 2; Swap Players 1 and 2 trades them (with one controller, it then plays Player 2 and the keyboard Player 1).
  • Mouse, on a HOME and in the menus (never in a game): click a game for its details, double-click it to play; click a menu item to choose it, or a button hint to press that button; right-click goes back; the wheel moves through the games.
  • Alt+Enter or F11: full screen, borderless; the window remembers it.

Studio menu → Play on PC Settings… changes the keys, the picture (TV proportions or square pixels, whole-number scaling) and the controller order.

HOME Settings (on a HOME in the game window: START › Settings) has Controllers & Keyboard, Gameplay Defaults, Selected Game Settings for the game you highlighted, and HOME Music (On or Off, for this computer).

Starting a Game

Every time a game starts (Play on PC, a game on a HOME, or a double-click), it asks first, before the game runs:

  • Load Last Used Save: the slot you last loaded or saved for this exact game, with its number and time.
  • Load a Save Slot…: choose any of the four slots.
  • Start New Game: the game starts from its title screen. Every save slot and the game's own cartridge save are kept as they are.
  • Back (or Close Game) changes nothing.

A choice that can't be used says why, for example when no slot is saved yet.

The Game Menu

Hold SELECT + START for three seconds, on either controller, to pause and open the game menu. While you hold them the game waits, and it goes on if you let go sooner; pressed together, SELECT and START never reach the game. Esc or closing the window opens the menu too, so nothing ends by accident. If the game window loses focus, the game pauses at once and says so; choose Keep Playing to go on. On a HOME, the same three seconds open the HOME menu: Controllers, Full Screen, and Close and Return to Studio to close the window, so everything works from a controller.

  • Keep Playing closes the menu.
  • Save to a Slot…: choose one of four slots (saving over a slot asks first); then keep playing or leave.
  • Load a Save Slot…: the game goes back to that slot's moment (it asks first).
  • Exit Without Saving (from HOME: Return to HOME Without Saving) writes no slot; the game's own cartridge save works as usual.
  • Game Settings…, Controllers… and Full Screen.

Game Settings and Rapid Fire

Each game version has its own Game Settings: in its details (Game Settings…), on a HOME (Game Details › Game Settings, or HOME Settings › Selected Game Settings…), and in the game menu.

  • Rapid Fire (Turbo): hold A or B to repeat presses automatically. Works with your controller or keyboard. A and B for each player, and the speed (Slow, Medium or Fast).
  • Swap A and B in this game, and its picture (TV proportions or square pixels, whole-number scaling).
  • Each choice can be Use Default, which follows Gameplay Defaults (rapid fire; off unless you change it) or Play on PC Settings (picture). A choice you set for one game stays when the defaults change. Reset Settings for This Game puts every choice back to Use Default; saves are kept.
  • Changes from the game menu apply when the game goes on; changes in Classic Cart Studio apply the next time the game starts.
Game Settings for one game version.

Saves

  • The four save slots are your saved moments. Nothing is saved to a slot unless you choose one: leaving, closing the window or losing focus never saves a slot by itself.
  • Games that save on the cartridge, such as The Legend of Zelda, keep that save automatically, as on the console.
  • Saves belong to the game file, not to a collection: the same version shares them in every collection, and from its details or from a HOME.
  • A save is written completely or not at all. If writing fails, the game window says so and stays open: try again, keep playing or leave without it.
  • A save made by another version of the game player is marked Cannot be used and never loaded; the file is kept.
  • An automatic save from an earlier test version of Classic Cart Studio is kept: the start choices offer Recover an Earlier Automatic Save… to copy it into a slot you choose.
  • They stay on this computer, in %LOCALAPPDATA%\ClassicCartStudio\saves, and Back Up Everything includes them. They are not sent to the console, and the console's saves are not read.

Backups and Recovery · two kinds of backup, and what to do after an interruption

There are two kinds of backup, kept in different places.

  • Console backups are the way back to factory software: the original kernel and NAND, read before any change and verified. Keep copies in two places.
  • Preparation backups are made on this computer before every Prepare: the previous selection and files are kept, so any run can be undone.

If Something Is Interrupted

  • During Prepare: the Studio rolls back to the previous setup and says what happened. Nothing is left half-written. Run it again once the cause is fixed.
  • Hakchi2 CE does not start after Prepare: the lineup is still prepared and verified. Start Hakchi2 CE yourself, or undo the run from the undo point shown.
  • A transfer to the console is interrupted (cable, power): reconnect and synchronize again; Hakchi2 CE transfers only what is missing.
Never turn the console off during a kernel step.

About the Technology · what is under the hood

Hakchi2 CE 3.9.3 handles the console side: custom kernel, extra storage, game folders, modules (hmods), hiding built-in games, synchronizing. The Studio does not reimplement any of it.

The Studio writes your lineup in the exact layout Hakchi2 CE reads (one folder per game with the ROM and its .desktop entry, plus the selection in Hakchi2 CE's settings) and leaves the console to Hakchi2 CE.

  • Identification: the SHA-256 of each ROM file and of its headerless PRG+CHR data, matched against No-Intro and the NesCartDB and Mesen cartridge databases. Headers for headerless files come from those databases, never guessed.
  • Background Helper: Classic Cart Studio for Windows runs a helper process with a small HTTP server on 127.0.0.1:8765 for its own window (it is not a Windows service). The website may hand a collection or package to it (from ClassicCartStudio.com only) and nothing else. Its data lives in %LOCALAPPDATA%\ClassicCartStudio.
  • Preparation: every run keeps a backup and a journal; a run with no changes changes nothing; an interrupted run rolls back.
  • Play on PC: the game player (ccs-player.exe) runs the FCEUmm emulator (libretro-fceumm, built in, one pinned version) and the same HOME program as Preview on TV, in its own window. It reads the game files the app keeps and writes saves only to its own folder.
  • Console steps: they run in a separate worker process that, in this version, can talk only to a simulated console; physical installation is disabled in the code.
  • Backups: a .ccs file is a ZIP archive (ZIP64 when large) with a contents list of SHA-256 checksums and one ROM file per game, each verified by its content hash. A Full Studio Backup is the same format with every collection, the Game Settings and, from the Windows app, the saved games. It is made and read on your device only; Classic Cart Studio runs no service that receives backups or ROM files.
  • Source and formats: the project repository documents the collection and .ccs formats; see Credits for licenses.

Troubleshooting · short answers

Installing and Preparing

Install on NES Classic checks and prepares but does not install

That is expected: installing from the Studio is not available in this version. Preparing is complete and verified. Installing Your Collection explains the transfer in Hakchi2 CE; the console steps can be rehearsed against a simulated console.

I cannot find Install on NES Classic or Console Menu Setup

Both appear while an NES Classic Lineup is open. Open or create one from My Collections ▾.

Install on NES Classic shows a setup screen

The Studio works with Hakchi2 CE 3.9.3, exactly that build. If it is missing, the Studio offers to set it up from the verified copy included with the app. If a different build is present, it says so and leaves it alone.

Prepare says Hakchi2 CE is open

Hakchi2 CE rewrites its settings when it closes, so the Studio never changes them while it runs. Close Hakchi2 CE and prepare again.

Prepare says the console is connected

Prepare works only on this computer and refuses to run with the console attached, so nothing can reach the console by accident. Disconnect it and prepare again.

“Cannot be prepared” or “Game File Missing”

One of two causes:

  • The ROM file has no header, and the Studio will not guess a mapper.
  • The app's copy of the file is gone. Use Locate File… with a file that has identical content.
Hakchi2 CE's games changed since I loaded them

Something changed the selection outside the Studio. Check Collection offers to review the differences, reload from this computer, or keep your changes. Nothing is overwritten until you choose.

Windows asks for administrator approval

Only the console USB driver needs it, once, after you choose Install USB Driver…. The Studio never runs with administrator rights.

Website and Backups

The website shows an invitation instead of the action

Actions that need your files (Install on NES Classic, Add Your Own Game, Find ROM Files…) happen in Classic Cart Studio for Windows. Choose Open in Windows App: the app opens with your collections, or you are taken to ClassicCartStudio.com/app to install it.

“Local network access blocked” or “could not be reached”

Edge and Chrome ask once whether a website may reach apps on your computer. If you declined:

  1. Select the lock icon left of the address.
  2. Choose Permissions for this site.
  3. Set Local network access to Allow.
  4. Reload the page.
Back Up is not available

Every listed game needs its ROM file. The dialog lists the games without one: add their files (Choose ROM Files… on the website, Add ROM Files… in the Windows app). A backup is made only when it is complete.

An old shared collection link no longer works

Shared links are no longer used. Restore the collection from its .ccs backup instead.

A file “could not be read” while adding games

The summary names the reason: not a ROM, too small, unsafe paths in an archive, suspicious compression, a damaged ZIP. The file is skipped; nothing else is affected.

Classic Cart Studio for Windows

The app says it is older than the website expects

Install the latest version from ClassicCartStudio.com/app (verify the hash, run the installer). Your games and settings are kept.

SmartScreen says “unknown publisher”

The installer is unsigned. Verify its SHA-256 as described in Installing Classic Cart Studio; if it matches, choose More info → Run anyway.

“Classic Cart Studio couldn't load its interface”

The interface is installed with the app and served on this computer, so the app's Background Helper did not start. Choose Try Again; if it keeps happening, open Diagnostics or reinstall. Your collections, imported games and settings are untouched.

“Classic Cart Studio could not start”

The app runs a Background Helper on this computer (port 8765). If another program uses that port, close it and choose Try Again. Diagnostics in the app's menu shows the details and where the logs are.

If the Background Helper stops later, start Classic Cart Studio again from the Start menu. Your collections and imported games are unaffected.

I chose Open in Windows App and nothing arrived
  1. Edge asks whether the website may access apps on your device: choose Allow.
  2. Windows asks whether to open Classic Cart Studio: choose Open.
  3. If the app is open but shows nothing, wait a few seconds. It checks for collections when it starts and every 15 seconds after that.

The website keeps your collections either way. You can also back one up as a .ccs file and open it in the app.

Play on PC is unavailable for a game

The note under the button names the reason: the ROM file is not on this computer, it is a different version, or it has no header the Game Library can supply. Add the file of that exact version with Add Your Own Game (Choose Files… or Choose a Folder…); for your own game, Locate Missing ROM File… in its details. Only one game window runs at a time; close it to start another.

A controller does nothing in the game window

Xbox-compatible controllers work at once. Set up any other controller once: hold one of its buttons that does nothing for three seconds, or choose Controllers → Set Up a Controller… in the game menu (press Esc to open it). The game window reads controllers only while it is the active window; the game pauses while another window is in front. With more than two controllers connected, only the chosen ones (or the first two) play: Controllers → Choose Player 1's Controller… lists them all.

Starting the app again opened nothing new

That is intended: Classic Cart Studio runs one window at a time, and starting it again brings that window forward.

The console steps say “install the latest version”

The app on this computer is older than these steps need. Install the latest version from ClassicCartStudio.com/app; your games and settings are kept.

Does a .ccs file from the website include the games?

Yes. Every .ccs file, from the website or the Windows app, contains the verified ROM file of every game it lists. On the website, choose Choose ROM Files… in Back Up Collection and pick the files (or a ZIP or .ccs file that has them); the website uses them for this visit only and does not keep them. The Windows app uses the copies it keeps on this computer. If some files are missing, add them first. The lists-and-settings file (Studio menu → Save Lists and Settings…) is a different file: JSON, without game files. Back Up Everything makes a complete .ccs backup of the whole Studio.

Where the Windows app keeps things

In %LOCALAPPDATA%\ClassicCartStudio:

  • logs;
  • hakchi-staging: backup and journal for each Prepare run;
  • personal: copies of your own games;
  • console: installation plans and rehearsal records;
  • saves: Play on PC saves, one folder per game file;
  • play and player-*.json: the game window's recent sessions and its settings.
