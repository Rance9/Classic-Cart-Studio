Getting Started · what an NES Classic is and what customizing means

The NES Classic Edition (2018 North American model) is a small console with 30 built-in games and a very simple menu. Inside it is a tiny Linux computer. "Customizing" it means putting your choice of games into that menu: keeping some of the 30 built-in games, hiding others, and adding games you own. Nothing about the console's look changes; the menu simply shows the games you chose.

1ChoosePick games in the Game Library. That list is My Collection.
2PrepareThe Studio prepares the game files and the selection on this computer and checks its work.
3InstallWith the console connected, the prepared collection is transferred. In this version the transfer itself is still a separately approved step.
4PlayDisconnect, switch the console on, and the menu shows your collection.
You own the games you add. The Studio never downloads commercial games and never shares your files. It helps you organise and install what you already have.
What actually changes on the console

A small program called a custom kernel is loaded once so the console accepts changes; the original one is backed up first. Game files and a menu description are copied into the console's user storage. Built-in games you did not choose are only hidden from the menu (their data stays on the console); showing them again is a matter of selecting them. The Studio keeps enough information to undo every change it made on this computer.

Think of a playlist. The Game Library is every song available; My Collection is the playlist you are building; Install on NES Classic is pressing play on the console.

Website vs Companion · what runs where

The Studio has two parts. The website runs entirely in your browser: browsing, filtering, planning a collection, saving it to a file and loading it back all work with nothing installed, and nothing you do there leaves your computer (your collection lives in the browser's storage). The companion is a small Windows program that does the things a website cannot: read the games already set up on this computer, keep copies of game files you import, prepare a collection for the console-management software and open that software.

1Website onlyExplore the library, build and save collections, read this guide. Buttons that need the companion say so and offer Connect to Your Computer.
2Website + companionEverything above plus Load an Existing Collection, Add Your Own Games (files, folders, ZIPs), Locate Game File, and Check / Prepare on the Install screen.
3ConnectingClick the connection pill (top right of the toolbar) → Connect. The companion opens a small window on this computer asking whether the website may use it; click Allow. The permission is for this website only, for this session, and you can disconnect at any time.

The companion listens only on your own computer (address 127.0.0.1); nothing on the network can reach it. If your browser asks whether the website may access devices on your local network, that question is about this connection — allow it for this site.

Neither part ever sends anything to the console. The console-management software (Hakchi2 CE) is what talks to the console, under your control, and this version of the Studio shows those steps rather than performing them.

Installing the Companion · download, verify, install, upgrade, uninstall

1DownloadConnection pill → Get the companion, or the project's Releases page on GitHub. The file is NESClassicCollectionStudio-Setup-<version>.exe.
2Verify (recommended)Open Windows PowerShell and run Get-FileHash -Algorithm SHA256 "$env:USERPROFILE\Downloads\NESClassicCollectionStudio-Setup-<version>.exe". The printed hash must equal the SHA-256 shown next to the download (there is a Copy button) and in SHA256SUMS.txt on the release. Letter case does not matter. If it differs, delete the file and download again.
3InstallRun the installer. It installs for your user account only (no administrator rights) under %LOCALAPPDATA%\Programs\NESClassicCollectionStudio and adds a Start-menu entry. Windows SmartScreen may show "unknown publisher" because the installer is not code-signed (see below); choose More info → Run anyway only after the hash matched.
4Start and connectStart NES Classic Collection Studio Companion from the Start menu, come back here and click the connection pill → Connect → Allow.

Upgrading: run the newer installer; it replaces the program and keeps your data. The website tells you when the companion is older than it expects. Uninstalling: Windows Settings → Apps → NES Classic Collection Studio Companion. Your imported games, personal games and collections stay in %LOCALAPPDATA%\NESClassicCollectionStudio until you delete that folder yourself.

Why the installer is not code-signed

A Windows code-signing certificate costs money and binds a legal identity; the project does not have one yet. Instead every release is built by a public GitHub Actions workflow from the tagged source, the workflow run is linked from the release notes, a build-provenance attestation is attached, and the SHA-256 of the installer is published. The hash check in step 2 is what protects you.

What the companion installs and changes

Program files under your user profile, a Start-menu shortcut, an optional desktop shortcut, and a nesstudio:// link type for your user account (used only to bring the companion forward). No service, no scheduled task, no driver — the console USB driver is a separate, explicit step on the Install screen that asks for administrator approval because Windows requires it for drivers.

The 30 built-in games

They are in the Game Library like any other game and are selected the way you select everything else. A selected built-in game stays visible on the console; an unselected one is hidden there (never deleted). Choosing a game the console already has never installs a second copy.

Counts in the toolbar are separate on purpose: shown is what the current search and filters leave visible, selected is My Collection, and library is how many games exist. Filtering never deselects anything.

Understanding Game Versions · regions, revisions, re-releases, alternate ROMs

One game often exists as several ROM files: a USA release and a European one, a first printing and a later revision with bug fixes, a Japanese original, a prototype, a modern re-release. The Game Library shows each game once; the small version chip next to the title (for example USA · Rev 1▾ 8) opens the list of versions.

WordMeaning
RegionWhere the cartridge was sold (USA, Europe, Japan, World…). Mostly language and small differences.
Revision (Rev 1, Rev 2…)A later manufacturing run with fixes. The highest verified US revision is usually recommended.
Re-releaseThe same game as shipped in a later product (Virtual Console, a collection cartridge). Bytes may differ slightly.
Prototype / Beta / SampleUnfinished or demonstration builds. Interesting, not what you expect from the box.
Pirate / UnlicensedNot published under Nintendo's licence. Some are legitimate independent releases; some are copies.
Translation / HackA fan-modified ROM. Kept as its own version, related to the original.

Your choice is kept exactly. If you pick a version, the Studio never switches it for you. A game you loaded from this computer keeps the exact version that was there. Wanting two versions of one game on the console at the same time is possible: tick Keep more than one version of this game in the version list; the Tray then shows both.

How the Studio tells versions apart

Every ROM file is identified by the exact bytes it contains (a cryptographic hash), not by its file name. Two files with different names but identical bytes are one version with two names; two files with the same name but different bytes are two versions. Names from the No-Intro database are used as the release identity when the bytes match; when they do not match any database, the file name is shown but the identity is marked as unverified.

Extended Library · what it contains and why you might switch it on

By default the Game Library shows a curated set of North American releases with complete information. The Extended Library switch (toolbar, second row) adds everything else the Studio knows: other regions, prototypes and betas, unlicensed and pirate releases, re-releases, translations, multicarts and less-common titles, plus additional versions of games you already see.

  • Switching it on never duplicates a game: extra versions appear inside the existing version chip.
  • Some entries have incomplete information or uncertain compatibility; the Studio says so instead of guessing. That does not mean they are unsafe — it means less is known.
  • Switching it off hides those games from browsing but never deselects them: anything selected stays in My Collection and in the Tray, marked Extended.

Loading Existing Games · from this computer or from a saved file

My Collection ▾ → Load Existing Collection offers two sources.

Selected Games Only vs Entire Game Library

Selected Games Only brings in the games currently chosen for your NES Classic. Entire Game Library also brings in games that are set up but not currently chosen: they become available in your games; exactly the chosen ones stay selected. If 400 games are set up and 75 are chosen, you get 400 available and 75 selected — never 400 selected.

Games the Studio recognises are matched by their bytes, never by name. Games it does not know stay as personal games with their original name and version. A game whose file is missing is listed, not dropped, so you can bring the file back later.

Adding Your Own Games · personal ROM files become catalog entries

1Choose a fileMy Collection ▾ → Add Your Own Games → Add one file and describe it, then pick a .nes file or a ZIP that contains one. (For many files at once, see Adding Games from Files and Folders.)
2The Studio reads itIt works out the file type, computes the identity hashes and reads the cartridge information from the file's header.
3Known or newIf the bytes match a game in the Game Library, that game is used (no duplicate). Otherwise a new personal game is created with an editable title, version label, description and artwork.
4Keep a copyThe Studio keeps its own copy so the collection keeps working if you move the original. Your original file is never modified.

Personal games take part in everything: search, grid, list, Tray, favorites, versions, Technical Details, saved files and preparation. They are marked Personal Game.

Files without a header (no cartridge information inside) cannot be prepared for the console, because the Studio does not guess cartridge types. The game is kept; Technical Details explains what is missing. Game File Missing — Locate File appears when the Studio's copy is gone; relinking checks that the file you point to has the same bytes.

Adding Games from Files and Folders · ZIP archives, bulk import, exact identification

My Collection ▾ → Add Your Own Games offers three ways in: files (pick one or many ROM files or ZIP archives), a folder (everything inside it and its sub-folders), or one file you describe (homebrew with a title and artwork). The first two run as a background job with progress, a running list and a summary; you can stop at any time, and whatever was already examined stays.

1ReadEach file is opened by the companion on this computer. ZIP archives are opened in memory; each ROM inside is a candidate. Archives with unsafe paths, members larger than any NES game or suspicious compression (a "zip bomb") are refused and reported, never extracted.
2Identify by contentThe file's bytes are hashed (with and without the 16-byte header). A game is recognised only when the hash is exactly a known version in the library — file names are never trusted, and nothing is ever substituted.
3Keep a copyKnown versions get one managed copy per version (duplicates are counted, not copied twice). Unknown files become personal games. Your original files are never changed, moved or deleted.
4Add to the collectionWhen the job finishes, Add the matched games to the collection selects them in one click; personal games appear with the Personal badge.
Only files you own may be imported (for example dumps of your own cartridges). The Studio never downloads games and never ships them; see Your Files, Ownership and Redistribution.

Missing Game Files · pending dependencies and Locate Game File

The library knows thousands of versions by their exact hashes, but a version can only be prepared when this computer has its file. A selected version without a file is a pending dependency: it stays in the collection, the Check step lists it as "missing ROM payload", and the collection cannot be prepared until the file is found. Nothing is substituted — a different revision or region is a different game to the console.

1Locate Game File…On the Check screen, the missing game's row offers Locate Game File…. Pick the file (or a ZIP that contains it) on this computer.
2Exact checkThe companion hashes it and accepts it only when the content is exactly that version. A wrong file is refused with a clear message and nothing is kept.
3DoneThe managed copy is kept and the game becomes available; Check again and the row turns green.

Alternatively, import a folder (previous chapter): every known version found in it becomes available at once. The connection pill's details show how many of your selected games have files on this computer.

Your Files, Ownership and Redistribution · what this project does and does not do with games

The Studio is a collection manager. It identifies games by public identification data (titles, publishers, hashes compiled from the No-Intro, NesCartDB and Mesen databases); it contains no game files and no way to download them. The game files it works with are the ones you provide and own, such as dumps of your own cartridges, and the 30 games that came with your console.

  • Copies the companion keeps stay on your computer and are never uploaded or shared by the Studio.
  • Collections you save to a file contain names, hashes and your choices — not game data — so they can be shared freely.
  • Links to the Internet Archive or similar sites in the documentation describe where identification data comes from; they are not an invitation to download copyrighted games, and the Studio will not do it for you.
  • The pixel characters on this site are original drawings for this project; no box art or Nintendo artwork is distributed.

Saving and Loading Collections · what a collection file is, and is not

Save / Load ▾ → Save Collection to File writes a small text file (JSON) describing your collection: which games, which exact versions, your built-in game decisions, your personal games' names and identities, and the state the collection had reached. Load Collection from File opens one. The Studio also keeps an automatic draft in this browser, so a refresh or closing Edge loses nothing, and snapshots before New Collection, before loading and before restoring (Restore a Previous Collection).

  • A collection file contains no game files. On another computer it lists what it needs and lets you locate missing files; games it cannot find are reported, never substituted.
  • Older collection files from this project (three earlier formats) open as well; they are read with their original meaning and saved again in the current format.
  • Saving a file is not installing. Preparing on this computer is not installing either. The status line keeps the two apart.

Moving to another browser or to the website. Save / Load ▾ → Export Studio Data writes one file with your favorites, snapshots, settings and the current collection; Import Studio Data on the other side merges favorites and snapshots and offers to restore the collection. The Studio keeps everything in the browser you are using, per website address, so this file is the way to carry it across — no account or login is involved.

Connecting Your NES Classic · cables, buttons, modes

You need the console, its micro-USB cable (the one it charges from), and this Windows computer with the Studio running. The HDMI cable can stay in the TV.

1USBSmall end into the console's USB port (back), large end into the PC. Use a data cable, not a charge-only cable.
2First time onlyWith POWER off, hold RESET, switch POWER on, keep RESET held about 4 seconds, release. The console is now in a listening mode ("FEL") that Windows recognises as a device. The Studio tells you when this is needed.
3Already prepared consoleJust switch POWER on normally; Windows recognises it as a network device.
4DriverA small Windows driver is needed once. The Studio checks for it during setup and installs it only when you ask (Windows asks for administrator approval).
Only the 2018 North American NES Classic Edition (CLV-101) is supported by this Studio.

First-Time Console Preparation · what happens before a console can accept games

A fresh console runs only its original software. Before it can show additional games, four things happen once, in this order. Each is a real change to the console and is done only with your explicit go-ahead; in this version of the Studio they are described, not performed.

1BackupThe console's original kernel and storage are read and saved on this computer, and verified. This is what makes a return to factory software possible.
2Custom kernelA modified kernel (from the Hakchi2 CE project) is written so the console can mount user storage with your games. The original is kept in the backup.
3ModulesOptional additions such as the RetroArch emulator, needed by some games. Installed only when a game in your collection needs them and you approve.
4First transferYour prepared collection is copied over; built-in games you did not choose are hidden.
Never assume a console is untouched just because you did not prepare it. The console-management software reports whether a custom kernel is already present; the Studio shows that before anything else.

Doing the transfer with Hakchi2 CE 3.9.3 yourself (exact steps)

Because the console-management software has no automation interface for transfers, the transfer is a click in that application. After Prepare Games the Studio has already filled in everything: the application opens with exactly your collection ticked.

  1. Finish Prepare Games in the Studio (status: prepared on this computer). Optionally use Verify in the console-management app: it opens the application and reads its list without clicking anything.
  2. Connect the console (chapter Connecting Your NES Classic). For a console that already has the custom kernel: POWER on. For a first-time console: use the RESET procedure; the application will offer the kernel steps — read the Backups chapter first.
  3. In the application, the status strip at the bottom must say Online. The list on the left is your collection, already ticked.
  4. Click Synchronize selected games with mini (bottom right). A transfer window shows progress. Do not disconnect while it runs.
  5. When it reports completion, close the application; the Studio's checks still show what is prepared.
  6. Disconnect the USB cable, switch POWER off and on, and check the menu on the TV: the built-in games you kept, plus your added games.
The Studio's own step 6 stays disabled until console writing has been reviewed and approved for this project; the steps above describe the standard procedure of the console-management software for when that time comes.

Updating an Existing Console · later changes are smaller than the first setup

Once a console has been prepared, changing the collection is routine: adjust My Collection, run Prepare Games (only what changed is prepared; games already prepared are reused by their bytes; games you removed are unselected, never deleted), connect the console with POWER on, and transfer. No kernel is reinstalled for adding a game, and modules are only needed when a new game requires them.

If the games set up on this computer changed since you loaded them (for example someone used the console-management application directly), the Studio notices at Check Collection and asks whether to review the differences, reload what is on this computer, or keep your changes. It never overwrites a newer setup silently.

Future: Automatic Console Sync · what a later version may add, honestly stated

Today the Studio prepares everything on the PC and hands the actual console writing to Hakchi2 CE, which you operate yourself. A later version may drive those steps from the Install screen: detect the console, confirm the backup, synchronise the prepared collection, and read the result back. None of that exists in this version, and the Install screen says so on every step that is not available.

Whatever is added later keeps the same rules: nothing is written to the console without an explicit go-ahead, the original software stays backed up and restorable, and every step reports what it actually did.

Emulators and Compatibility · why some games use the built-in emulator and others need RetroArch

The console plays NES games with its own emulator (called kachikachi inside the system). It supports the cartridge types used by the built-in games and many others, but not all. Cartridges with unusual chips ("mappers" the emulator does not know) need a different emulator, RetroArch with the FCEUmm core, which is an optional module on the console.

  • The Game Library shows a recommended emulator for every game, based on documentation and community reports. Nothing has been tested on this particular console; the Studio says that everywhere the recommendation appears.
  • A game that needs RetroArch is prepared anyway; the collection then reports a prerequisite (the module is not installed) rather than pretending it will run.
  • Games with known problems (a few titles with sound glitches or crashes on the built-in emulator) carry a note with their source. Technical Details shows the evidence.

Special Controllers · accessory limitations, including light guns

The NES Classic has two standard controller ports (the Wii-style connector). Games that need other hardware — the Zapper light gun, the Power Pad, R.O.B., the Four Score for 3–4 players, the Miracle Piano and others — are marked in the Game Library with a controller icon and listed in the Tray's hardware warning.

  • Light-gun games (Duck Hunt, Hogan's Alley, Wild Gunman…): the original Zapper works only with CRT televisions, and no light-gun solution has been verified on this HDMI console. These games stay marked unverified; they can be installed, but the Studio does not claim they are playable.
  • Power Pad, R.O.B., Vaus, keyboards, pianos: no supported way to connect them; marked unsupported.
  • Four Score (3–4 players): not supported with the console's two ports.
  • Games playable with standard controllers in some modes are marked optional or mode-specific.

The Studio does not recommend buying accessories and does not assume compatibility with hardware that has not been verified on this console.

Backups and Recovery · why backups matter and what to do after an interruption

Two kinds of backups exist. Console backups (the original kernel and storage, read before any change) are what make a return to factory software possible; they are verified by checksum and kept in two places. Preparation backups are taken on this computer before every Prepare: the previous selection and files are kept so that any run can be undone.

If something is interrupted

  1. Preparing on this computer: the Studio restores the previous setup automatically and tells you what happened and what to do; nothing is half-written. Repeat when the cause is fixed.
  2. The console-management application does not start after preparing: the collection is still prepared and verified; start the application manually or undo the run from the undo point shown.
  3. A transfer to the console interrupted (cable, power): reconnect and transfer again; the console-management software transfers only what is missing. Never switch the console off during a kernel step.

Troubleshooting · plain answers first, details when you want them

"Install on NES Classic" only checks and prepares — it does not install

Correct for this version: installing on the console is disabled until console writing has been reviewed and approved for this project. Preparing on this computer is complete and verified; the chapter Installing Your Collection explains the manual transfer.

The button says "set up" or shows a setup screen

The Studio checks that the console-management software (Hakchi2 CE 3.9.3, exactly that build) is present on this computer. If it is missing, it offers to set it up from a verified package; if a different build is present, it says so and does not replace it.

"The console-management application is open — close it first"

The Studio never changes that application's settings while it is running (it would overwrite them when it closes). Close it, then prepare again.

"The console is connected — disconnect it first"

Preparing is a PC-only step; the Studio refuses to run it with the console attached so that nothing can reach the console by accident.

A game shows "cannot be prepared" or "Game File Missing"

Either the file has no cartridge information (header) and the Studio will not guess one, or the Studio's copy of your personal file is gone — use Locate File; the file you choose must have the same bytes.

The games on this computer changed since I loaded them

Someone (or the application itself) changed the selection outside the Studio. At Check Collection the Studio offers: review the differences, reload what is on this computer, or keep your changes. Nothing is overwritten until you choose.

Windows asks for administrator approval

Only the console USB driver needs it, once, and only after you click Install console driver. The Studio itself never runs elevated.

The connection pill says "Connect to Your Computer" but nothing happens

The companion must be running (Start menu → NES Classic Collection Studio Companion). If it is, click the pill → Connect; a companion window asks you to Allow. If your browser blocked the pop-up, use the link in the dialog or type the 6-digit code shown by the companion.

"Local network access blocked"

Microsoft Edge (and Chrome) ask once whether a website may talk to programs on your computer. If you declined, click the lock/tune icon left of the address → Permissions for this site → Local network access → Allow, then reload.

"Companion needs an update"

The website expects a newer companion than the one installed. Download the current installer (connection pill → Get the companion), verify its hash, run it; your data is kept.

Windows SmartScreen says "unknown publisher"

The installer is not code-signed. Verify the SHA-256 as described in Installing the Companion; if it matches, choose More info → Run anyway.

The companion window says the port is in use

Another program listens on port 8765, or an older companion is still running. Close it (or restart Windows) and start the companion again.

The companion was closed or restarted

Connections are forgotten when the companion closes, on purpose. Start it, click the pill → Connect → Allow again. Your imported games and collections are unaffected.

A file "could not be read" during import

The summary lists the reason: not a ROM, too small, an archive with unsafe paths or a suspicious compression ratio, or a damaged ZIP. Such files are skipped; nothing else is affected.

Technical details for advanced users

The companion keeps its data under %LOCALAPPDATA%\NESClassicCollectionStudio: logs\companion.log (no tokens), exports (saved collection files), hakchi-staging (every preparation run keeps a backup, a journal and a ledger), personal (your imported and personal game copies). The collection file format and the acceptance evidence are described in the project repository's documentation.
